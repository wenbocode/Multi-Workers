# Changelog

## [Unreleased]

### Added

- Added L2 read-cap injection to conductor dispatch (feature-l3-readcap-injection): `autopilot/dispatch.py::_read_scope_caps()` now reads `l2_read_file_cap`/`l2_read_byte_cap` from the project's `.agenticdoc/_autopilot/config.json` and `render_task_md()` renders both into the task.md frontmatter between the `read_scope:` block and the `deny_globs:` block. Until now both fields were dead config: `config.py` parsed and validated them but no Python renderer ever emitted them, so every `read_scope` task (verifiers/reviewers/roadmap-writer) silently ran on the harness default of 8 read-ish calls / 65536 B. Measured consequence: 47 `cap-file`/`cap-byte` rejections across 6 workers / 3 project keys, and both the `feature-params-service` and `feature-tier-a-closeout` L3 `below` verdicts trace back to reviewers that could not read a single evidence file. Compatibility: an absent config file, a config without the two fields, or an invalid/unreadable config render byte-identically to the pre-fix renderer (no `l2_read_*` lines, zero footprint, no new dispatch failure mode; `config.py`'s fail-closed `ConfigError` contract is unchanged), and the caps stay hard upper bounds - a smaller configured cap still blocks (`rule=cap-file` / `rule=cap-byte`) and invalid values are never treated as unlimited. The Python side intentionally defines no cap fallback constant (single source: `config.py::DEFAULT_CONFIG` + `read-scope.ts::DEFAULT_READ_*`). Takes effect for tasks dispatched after the `mw serve` conductor process is restarted (dispatch runs in-process and the module is import-cached; the live conductor keeps the pre-fix renderer until then). `packages/multi-workers/test_autopilot_readcap_injection.py` adds 16 tests covering the injection, the frontmatter position, the byte-identical fallbacks, the small-cap / invalid-value reverse cases and the unchanged L3 criteria.

- Added the stalled-resume path and the advance-stall guard to the conductor (mw-autopilot-stall-feedback): `advance_stall_ticks` (default 5, range 1..50) is the number of consecutive failures of the same `(key, edge)` before the key is marked stalled, each failed `advance` event carries a machine-readable classification (`{edge} exit=N class=interface-drift|gate-blocked|timeout-env|other`) next to the raw error, and the streak is re-derived from a bounded timeline tail on every tick (no private state, so a conductor restart keeps it). A `stalled` gate answered `approve` now resumes the key — key-status back to `running`, the `gate-answered` consumption event plus a new `resume` event, and exactly one extra round (`_resume_credits` = its approved stalled-gate count, applied to the L2 / EXECUTE / L3 / repair budgets). Previously the gate question promised "人工介入后重试" while only `reject` was consumed (→ closed-legacy), so an answered `approve` was a no-op that left the key stalled forever. New timeline event types: `resume`, `l3-no-verdict`.

### Changed

- Changed the `/worker` slash command to accept `--type coding|review|research` and `--reason <text>`, matching the `dispatch_worker` tool surface; a configured role value that pi's model table cannot resolve is now refused at dispatch (see README 派工类型与模型覆盖门禁) instead of being sent as a custom model id.

- Changed `mw_common.TASK_TYPE_TO_ROLE` to be differentially locked against the TS-side `DISPATCH_ROLE_BY_TYPE` (both maps hardcode the literal in their tests).

- Changed `mw serve` to start the LLM proxy on demand: it only spawns when a port-routed provider (claude / claude-cli / deepseek) has credentials, since direct routes (timi, codex-native) never touch it. Fresh machines without the private `timi-proxy-cli` package used to crash the whole service at import (`ModuleNotFoundError`) even though only the direct timi route was in use — such setups now log `proxy disabled; direct routes only` and serve normally. When the proxy IS needed its death stays fatal, but the log now carries the exit code plus the `.mw/proxy.log` tail. `mw doctor` gained a `proxy_log` section that surfaces the last crash's exception line as the root cause behind "port not listening" symptoms (issue when the service is down, suggestion otherwise), and reports `proxy: disabled` when no proxy-routed credential exists.

- Changed the divergence criterion in `docs/dual-toolchain-practice-guide.md` §7 (mw-worker-progress-persist): read-only worker roles now have `progress.md` written for them by the framework (machine checkpoint lines) and can append self-assessment lines through the new basename-only `worker_file` tool, so "no progress.md at the 30-minute checkpoint" no longer distinguishes a diverging worker from a healthy one - the criterion now reads the absence of a self-assessment line. No Python behaviour changes; the paired coding-agent entry describes the mechanism.

### Fixed

- Fixed the autopilot L3 verdict provenance gap (feature-verdict-provenance-guard): the L3 verdict's deciding source was unverified, so a `repair` worker could rewrite an already-failed round's `workers/*-l3-*/output.md` after that round's own `trace.log` had ended (turning a `below`-shaped round back into a `meets` one), and `key-status=done` was accepted from a bare optimistic `.agenticdoc/_index.parallel` phase pointer with no on-disk done derivatives. Measured on the real corpus: re-running the guard over all 18 historical L3 rounds flips exactly 1 round - `feature-cigate-install-kit` `l3-a2`, whose `output.md` was written 44,400.7 s after that round's `trace.log` end and is byte-identical (both sections) to the same round's `report.md` - while the other 17 rounds are unchanged and no round moves `below`->`meets`. The fix has three parts: (a) write-side ban - `_repair_prompt` now forbids touching `workers/*-l3-*/` `output.md`/`report.md` and routes verdict-source correction exclusively through a re-review, with the `- L3 报告：` reference line byte-verbatim; (b) read-side forensics, fail-closed - `_verify_loop` records one append-only entry per L3 round in `.agenticdoc/<key>/l3-verdict-provenance.json` (T1: deciding-source mtime > same-round `trace.log` mtime + 60 s module slack; T2: byte-equal `report.md` sections written later; abstain with `anchor_path=null` when the round has no `trace.log`), and a `suspect=true` round can no longer resolve to `meets` (it dispatches the next reviewer, or is persisted `below` when the round budget is exhausted - the reviewer is the only outlet, never repair); (c) done-credential gate - `_mark_key_done` refuses `key-status=done` unless the on-disk done derivatives are present (`l3-verdict.txt == meets`, `l3-report.md`, >=1 `quality-gate-report-*.md`, `achieved.md` carrying the required sections), logs the refusal as a `config` timeline event and leaves the roadmap key `running`. Orthogonal to the three adjacent keys: `feature-l3-verdict-source-fallback` still decides *which* source is read (`output.md` first, `report.md` fallback, any FAIL => below) and its 15 tests stay green; `feature-l3-verdict-freshness` still decides *when* a verdict is refreshed/recomputed; `mw-done-closure-repair` still owns the `_done_transaction` gate-blocked reprompt path (`_done_transaction` and `closure.py` are byte-untouched). Compatibility: the sidecar file is new and append-only, `_VERDICT_VALUES == ("meets","below")`, the frozen `_parse_l3_output`/`_md_section` regions and the 3-tuple contract of `_l3_round_verdict` are byte-unchanged, the L3 dossier keeps its 5 columns, no config key is added (sidecar name and 60 s slack are module constants), and a normal terminal round costs 2 stats / 0 extra reads with no directory scans. Takes effect for L3 rounds handled by a conductor process restarted after the fix. `packages/multi-workers/test_autopilot_verdict_provenance_guard.py` adds 16 tests (8 reverse fail-closed cases) covering the guard, the abstain fallback, both prompt contracts, the done-credential gate and the frozen anchors.

NO MATCH: achieved.md missing pattern ...`), `_done_transaction` discarded the advance stderr (the `err` only fed the stall classifier) and returned `gated`, so the failure text never reached any repair loop.
