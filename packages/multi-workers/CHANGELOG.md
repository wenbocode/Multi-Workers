# Changelog

## [Unreleased]

### Added

- Added L2 read-cap injection to conductor dispatch (feature-l3-readcap-injection): `autopilot/dispatch.py::_read_scope_caps()` now reads `l2_read_file_cap`/`l2_read_byte_cap` from the project's `.agenticdoc/_autopilot/config.json` and `render_task_md()` renders both into the task.md frontmatter between the `read_scope:` block and the `deny_globs:` block. Until now both fields were dead config: `config.py` parsed and validated them but no Python renderer ever emitted them, so every `read_scope` task (verifiers/reviewers/roadmap-writer) silently ran on the harness default of 8 read-ish calls / 65536 B. Measured consequence: 47 `cap-file`/`cap-byte` rejections across 6 workers / 3 project keys, and both the `feature-params-service` and `feature-tier-a-closeout` L3 `below` verdicts trace back to reviewers that could not read a single evidence file. Compatibility: an absent config file, a config without the two fields, or an invalid/unreadable config render byte-identically to the pre-fix renderer (no `l2_read_*` lines, zero footprint, no new dispatch failure mode; `config.py`'s fail-closed `ConfigError` contract is unchanged), and the caps stay hard upper bounds - a smaller configured cap still blocks (`rule=cap-file` / `rule=cap-byte`) and invalid values are never treated as unlimited. The Python side intentionally defines no cap fallback constant (single source: `config.py::DEFAULT_CONFIG` + `read-scope.ts::DEFAULT_READ_*`). Takes effect for tasks dispatched after the `mw serve` conductor process is restarted (dispatch runs in-process and the module is import-cached; the live conductor keeps the pre-fix renderer until then). `packages/multi-workers/test_autopilot_readcap_injection.py` adds 16 tests covering the injection, the frontmatter position, the byte-identical fallbacks, the small-cap / invalid-value reverse cases and the unchanged L3 criteria.

- Added the RAG configuration manual and `mw rag init` template generator (mw-rag-config-guide): `mw rag init --project <dir>` writes a fully commented `<dir>/.mw/rag-servers.yml` (what every field is / values and default / example / consequence), appends a commented `rag:` section to `<dir>/.agenticdoc/target.yml` at the text level (existing comments and sections survive - never a YAML round-trip), and writes `<dir>/.mw/rag-roots.json` by default with `engine: "."` (`--no-roots` skips the file and comments the field out); it is zero-interaction (no prompt, `stdin=DEVNULL` safe), defaults to `enabled: []` so the placeholder server is never probed, refuses an existing file or `rag:` section unless `--force`, and `--dry-run`/`--print` write nothing. `packages/multi-workers/docs/rag-config-guide.md` documents all three files field by field (`transport`/`adapter`/`path_roots_file`/`sources`/`capabilities.{graph,chat,rewrite}`/`mcp.{url,token_env,timeout_ms}`/`skill.{dir,cli_entry,timeout_ms}`, the six `rag:` keys, the roles/phases item keys - `roles` additionally accepts `chat_budget`/`time_budget_s` - and `rag-roots.json`), four copy-paste examples (mcp-only OverCode / skill-only / both / dual-service with role+phase `require`), the command reference with exit codes, the five-layer success criteria, the failure signatures and the known pitfalls. `test_rag_docs.py` pins the manual's three template blocks byte-for-byte to `mw rag init --print` and asserts the documented field set equals the validator's (missing or extra turns red).

- Added configurable RAG integration (mw-rag-integration): the machine layer `~/.agents/rag-servers.yml` and the project layer `<control>/.mw/rag-servers.yml` are merged field-by-field (arrays replace wholesale, `null` deletes, per-field `origin` recorded) and joined with the `target.yml` `rag:` section (`enabled`/`default_server`/`roles`/`phases`/`budgets`). `mw rag list [--json]` prints the resolved server table with per-field provenance, `mw rag probe` checks reachability, `mw rag sync` installs the shipped `skills/mw-rag/SKILL.md` (sha256-compared, removed again for projects with an empty enable set) and `mw rag audit` is a read-only judgement over `<key>/rag/*.md` plus terminal worker `output.md`/`trace.log`: it parses the `rag_call`/`rag_fallback`/`rag-required-missing`/`rag-rewrite-degraded` evidence lines by key=value, applies `required = role.require OR phase.require`, and reports calls without verifiable citations (exit 0/1/2, stdout only unless `--out`). The launcher injects RAG token env values (tokens are only ever named in config as `token_env`) into the worker process environment, strips them from every other path, and refuses a spawn whose injected rag block fingerprint no longer matches the rendered block (`config torn (rag)`); the conductor renders the `<!-- mw-rag: v1 -->` block into task.md with a fingerprint over the enabled servers' static fields, the path_roots digest, roles/phases and budgets, and writes the `phase:` header when the owning key's phase is known (never guessed). `rag-research` is registered as a new dispatch type (role `research`, 11 tools) with `DispatchType.conductor_dispatchable=False`, so the conductor refuses to dispatch it while `/worker` can still request it. Requires `mw rag sync` plus a serve restart; projects without a `rag:` section are unaffected (no injection, no probe, no files). A route to the `overcode` reference service is `transport: mcp` with `token_env`, `skill`, or `both` (mcp primary, cli fallback for read-only tools on connect-level failures only).

The launcher gains a dedicated `_build_env` branch (injects only `ZAI_CODING_CN_API_KEY` + `PI_WORKER_TASK`; other providers' credentials stay stripped) and joins the direct-provider tuple in `_build_command` (explicit `--model` required - no default model; timi keeps its glm-5.3 default and the default route). serve treats it like timi: credentialed-but-portless routes never spawn the proxy (`proxy disabled; direct routes only (timi / zai-coding-cn / codex-native)`). The TS/Py prefix maps mirror each other on both sides of the parity lock.
- Added dispatch model defaults (mw-dispatch-models): configurable per-role models used when a task carries no explicit `model:` line. `mw model set <role> <provider/model>` / `show` / `clear` write `.mw/dispatch.yml` (roles: `main` = the PM window, `coding`/`review`/`research` map the dispatch task types — conductor types included: verifier/reviewer→review, phase-writer/repair/roadmap-writer→coding). Model values use the `prefix/model-id` namespace where the prefix selects the serving channel: `timi/`, `claude/` (direct anthropic, no mw proxy), `codex/` (pi's openai-codex provider, codex' own config), `deepseek/` (direct), and `codex_cli/`/`claude_cli/` (CLI executors). Resolution per spawn (launcher, single choke point): task.md `model:` > dispatch.yml role > `.mw/window-model` (recorded by the PM window's extension) > per-cli hardcoded default; a provider prefix overrides the entry's provider but never the cli, incompatible or unknown prefixes fall through to the next layer (explicit task.md values fail loudly instead). New direct-provider env branches (anthropic/deepseek/openai-codex) inject only their own credential and never point at the mw proxy. `/mw doctor` gains a `dispatch` section (parse errors are suggestions — a broken file never blocks dispatching). The same surface is reachable from a pi window via `/mw model show|set|clear` (agent-team-loop forwards to the CLI).

- Added `/update-agentictask` to the shipped machine setup: `mw setup` (bootstrap step 5) and `mw build --install` now install `agentictask-update.ts` — the pi global extension registering the `/update-agentictask` command — into `~/.pi/agent/extensions/`. The template is machine-independent: instead of the old hardcoded dev-machine mw.py path it resolves mw.py at runtime via `MW_PY` > the `.mw-py-path` sidecar (same source as the agent-team-loop `findMwPy`). Previously the command only existed on the dev machine as a hand-created file in the user's global extensions dir, so fresh machines never got it. Install is idempotent (identical copy skipped, drifted copy overwritten).

- Added pi `shellPath` auto-fill for fresh machines: `mw_common.detect_pi_shell_path()` (Windows-only; pwsh.exe before powershell.exe, mirroring pi's own resolution order) and `mw_common.ensure_pi_shell_path()` — an additive merge into `~/.pi/agent/settings.json` that fills a missing `shellPath`, replaces a stale one (file gone, e.g. settings copied from another machine), never overwrites a working value, and never rewrites a malformed file. Wired into `mw setup` (bootstrap step 5) and `mw doctor` (new `pi_shell` section; `--fix` applies the fill and records it under `fix.applied`; a broken shellPath is an issue, a missing one a suggestion). Rationale: pi resolves the bash tool's shell as user-shellPath -> working WSL bash -> PowerShell; a fresh machine has no shellPath, and WSL bash shadows the Windows python the user bootstrapped with — the PM agent's `python .../advance_phase.py` path then dies with "no shell". settings.json stays protected: the write happens only from explicit user-invoked commands (setup / bootstrap / doctor --fix) in a plain terminal, as a documented exception to the no-framework-write policy.
- Added `mw bootstrap`: fresh-machine one-shot covering the full chain in 8 steps — prerequisites (python >= 3.11, node >= `engines.node`, npm, git, and the credential-route status: missing credentials do NOT abort a fresh install (`~/.pi/agent/auth.json` cannot exist yet) — bootstrap warns, skips the service start (step 7), and points at the `--fast` re-run once credentials are configured, so steps 2-6 stay credential-free), `npm ci --ignore-scripts` on a fresh clone / incremental `npm install --ignore-scripts` on re-runs, root `npm run build` (network required: the ai build fetches the models.dev catalog), `npm link packages/coding-agent` (the global `pi` must be this fork — workers run `pi --provider timi` and the timi provider/models only exist here; verified via a link-target check: `npm root -g` + realpath must resolve to this repo's `packages/coding-agent`, rejecting a leftover registry install of the official package that would silently lack the timi provider — plus `pi --version`), `mw setup --build` (bundle + global extension + framework cache), idempotent `mw init` (warns when the AgenticTask framework ends up missing), `mw start` with a 30s PID-file wait (serve's route precheck runs before the PID write), and a final `mw doctor` verdict. `--fast` skips the npm install/build steps for credential-fix re-runs (requires a prior full bootstrap); `--no-start` leaves the service down and tolerates the expected service-not-running doctor issue. Re-runnable: every step is idempotent or self-verifying.

- Added `mw ue-toolchain` (dual-mode UE toolchain discipline — UE game dev: game repo + engine source repo + .uproject, MSVC/UBT; distilled from the frontline AssetImportGate practice guide now vendored at `docs/dual-toolchain-practice-guide.md`): `run <name> [--args=STR] [--watch PATH] [--out DIR] [--json]` executes a target.yml toolchain template from the control root and archives a run dir — `cmd.txt` (verbatim command), UTF-8 `run.log` (the `.log` extension quality gates scan), `exit.txt`, `errors.txt` + `meta.json` carrying the MSVC/UE signature scan (`error C`/`LNK####`/`error :` — the exit code is necessary but not sufficient); the mw exit code is the combined verdict (clean exit AND zero signature lines AND zero `--watch` drift) so scripts can gate on it, and differential acceptance (known-red baselines) compares two runs' `errors.txt` sets; `--watch` hashes files EOL-normalized before/after to prove nobody edited the sources while the command ran; `--out` redirects the run dir into key evidence. `targets` lists UE build target names from `<game>/Source/*.Target.cs` (read, never guessed); `hash` is the standalone EOL-normalized sha256 (engine repos on `core.autocrlf=input` flip CRLF→LF on checkout/rebase — byte-exact hashing reports false drift). `targets` discovery and the error signature set are UE/MSVC-specific; the run-evidence discipline and `hash` are toolchain-agnostic. 14 hermetic tests in `test_toolchain_cli.py`.

- Added the stalled-resume path and the advance-stall guard to the conductor (mw-autopilot-stall-feedback): `advance_stall_ticks` (default 5, range 1..50) is the number of consecutive failures of the same `(key, edge)` before the key is marked stalled, each failed `advance` event carries a machine-readable classification (`{edge} exit=N class=interface-drift|gate-blocked|timeout-env|other`) next to the raw error, and the streak is re-derived from a bounded timeline tail on every tick (no private state, so a conductor restart keeps it). A `stalled` gate answered `approve` now resumes the key — key-status back to `running`, the `gate-answered` consumption event plus a new `resume` event, and exactly one extra round (`_resume_credits` = its approved stalled-gate count, applied to the L2 / EXECUTE / L3 / repair budgets). One approval buys that round in each of the four capped budgets, and it is not reusable: each budget compares the credit against its own monotone round counter (derived from the append-only dispatch rows), so once the extra round is spent the same budget caps again and needs a fresh human decision. Previously the gate question promised "人工介入后重试" while only `reject` was consumed (→ closed-legacy), so an answered `approve` was a no-op that left the key stalled forever. New timeline event types: `resume`, `l3-no-verdict`.

### Changed

- Changed the `/worker` slash command to accept `--type coding|review|research` and `--reason <text>`, matching the `dispatch_worker` tool surface; a configured role value that pi's model table cannot resolve is now refused at dispatch (see README 派工类型与模型覆盖门禁) instead of being sent as a custom model id.

- Changed `mw_common.TASK_TYPE_TO_ROLE` to be differentially locked against the TS-side `DISPATCH_ROLE_BY_TYPE` (both maps hardcode the literal in their tests).

- Changed `mw serve` to start the LLM proxy on demand: it only spawns when a port-routed provider (claude / claude-cli / deepseek) has credentials, since direct routes (timi, codex-native) never touch it. Fresh machines without the private `timi-proxy-cli` package used to crash the whole service at import (`ModuleNotFoundError`) even though only the direct timi route was in use — such setups now log `proxy disabled; direct routes only` and serve normally. When the proxy IS needed its death stays fatal, but the log now carries the exit code plus the `.mw/proxy.log` tail. `mw doctor` gained a `proxy_log` section that surfaces the last crash's exception line as the root cause behind "port not listening" symptoms (issue when the service is down, suggestion otherwise), and reports `proxy: disabled` when no proxy-routed credential exists.

- Changed the divergence criterion in `docs/dual-toolchain-practice-guide.md` §7 (mw-worker-progress-persist): read-only worker roles now have `progress.md` written for them by the framework (machine checkpoint lines) and can append self-assessment lines through the new basename-only `worker_file` tool, so "no progress.md at the 30-minute checkpoint" no longer distinguishes a diverging worker from a healthy one - the criterion now reads the absence of a self-assessment line. No Python behaviour changes; the paired coding-agent entry describes the mechanism.

### Fixed

- Fixed the autopilot phase-advance channel resolving the wrong project root when the AgenticTask framework is installed outside the target project (mw-autopilot-advance-root): `autopilot/advance.py::locate_platform_dir()` now adopts a candidate only when its `detect_root.py --json` reports `PROJECT_ROOT` equal to the target project, and fails loud (`AdvanceError`, listing every candidate's reported root) instead of silently using a framework whose root resolution points at another repository - the 2026-09-22 blocker where every conductor tick's `advance` exited 1 and `mkdir`-ed empty key dirs into the framework repo's own `.agenticdoc`. Both subprocess calls (the `detect_root` probe and the `advance_phase.py` run) now pass `-X utf8`, so the framework's Chinese gate diagnostics no longer decode to `?` (cp936 stdio read back as UTF-8). The framework-side root fix (cwd-upward `.agenticdoc` scan in advance_phase/update_index/migrate_patterns/verify_project_memory plus `detect_root.py` CLI cwd preference) ships in the AgenticTask repo (wenbocode/AgenticTask d7004d0).

- Fixed the `mw rag` documentation and probe help to match the argparse surface (mw-rag-integration-fix): all four subcommands document the required `--project`, the phantom `probe --server` flag is gone, `--json`/`--key`/`--out` are listed with an exit-code table (`list`/`probe`/`sync` 0 or 1, `audit` 0/1/2), and `mw.py rag probe`'s help no longer claims "never a non-zero exit" (a config error returns 1). The `rag-rewrite-degraded` trace line is documented as the server's `meta.rewrite_degraded === true` (rewrite-failure degradation), not a multi-round-rewrite marker, and the tool-map table notes that its six rows are the six base tools while `rag_chat` is registered only for `rag-research`. Removed the dead `MW_RAG_ENABLED` env flag injected by `launcher.py` and its stale comment claiming the worker extension gates on it (it was never registered in the env docs and has no reader anywhere in the repo, so removing it changes no behaviour; the name is kept here so it stays greppable).

- Fixed the conductor retrying a permanently failing phase advance forever (mw-autopilot-stall-feedback): an `advance_phase.py` non-zero exit only produced two timeline lines and no state change, so a key whose advance could not succeed was retried every `poll_interval_sec` indefinitely — the 2026-09-22 E2Feature blocker spun `execute->verify` 2242 times over 2h35m (plus 3891 design→plan failures / 4h25m earlier the same day) and the whole stage stalled on that one key's dependency, with a healthy heartbeat making it look like work was happening. The same `(key, edge)` streak now hits `advance_stall_ticks` (default 5) and takes the existing stalled path (key-status + `stalled` gate + achieved draft + pattern file), which freezes the key by the usual skip rule; the failure class is recorded on the event so the reason names the real cause instead of a bare exit code.

- Fixed a crashed L3 reviewer being reported as a quality verdict (mw-autopilot-stall-feedback): when the review worker died before writing `output.md` (E2Feature: reviewer spawned with a bad model id → provider 403 within 6s), `_parse_l3_output` returned `below`, so the conductor dispatched a repair worker against a missing report, burned both L3 rounds, and marked the key stalled with `L3 below 2 rounds` — pointing the human at the wrong layer. Such a round is now `no-verdict` (new `l3-no-verdict` timeline event): the next review round is dispatched directly and the stall reason carries the worker status and task key.

- Fixed the terminal L3 verdict record never following the key's final L3 outcome (feature-l3-verdict-freshness): `autopilot/conductor.py::_persist_l3_verdict()` used a first-write-wins `if not verdict_file.is_file()` guard, so `l3-verdict.txt` + `l3-report.md` were frozen at the *first* L3 verdict a key ever produced. Measured impact on E2Feature: 3 of the 5 keys that have L3 rounds ended with a closure-dossier `l3 verdict` column that contradicts the key's own terminal round - `feature-mvp-closeout` / `feature-tier-a-closeout` (already published into the closed-book `stage-2-close.md` dossier) and `feature-params-service` - each showing `below` although the final round was `meets` and the key is DONE. The refresh is now *bidirectional* (`meets` overrides an earlier `below`, and a transient `meets` that degrades back to `below`/gated is overwritten again), *content-idempotent* per file (an equal target value leaves both bytes and mtime untouched, preserving the crash-retry guarantee the old docstring promised), copies the report as raw bytes (`read_bytes`/`write_bytes`, report first and verdict second so the authority never leads), and appends one `config` timeline event only when a file really changed (before -> after plus the report's source round; a no-op adds no noise). It closes the value domain to `{meets, below}` (a third state is a zero-write no-op) and accepts an optional `st` parameter for that trace. Compatibility: an absent `l3-verdict.txt` still gets written; a missing `report_src` still leaves the report untouched; an `OSError` on the report read/write is still swallowed while the verdict still lands; an `OSError` on the verdict write still propagates unchanged; the four call sites keep their exact verdict arguments and control flow. `l3-verdict.txt` is explicitly a *derived record*, not an append-only audit log - it is refreshed in place, and the authoritative history stays in the append-only timeline plus each round's worker `output.md`; this change touches no L3 criterion (`_parse_l3_output` / `_md_section` byte-unchanged), no threshold, no `read_scope`, and no published byte. Takes effect for terminal events handled by a conductor process restarted after the fix (a running conductor keeps the pre-fix function until then). `packages/multi-workers/test_autopilot_verdict_freshness.py` adds 8 tests covering the accident chain, report/verdict same-round byte equality, the three fail-closed reverse cases (no-resume `below`, resume-then-still-`below`, transient `meets` falling back), idempotent zero-write, the closed value domain and the unchanged L3 criteria.
