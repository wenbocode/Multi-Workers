# MW 计划裁剪与闭环检查

MW PM 在推进任务时，如果已经找到可行方向、正准备建议下一步，就把建议转成足以判断方向的最小验证，当轮执行并根据结果继续推进。比如准备建议复用一个已有入口，就先验证该入口能否覆盖当前用例，据结果落实复用或调整方案。最终验收按 `spec.md` 的 AC 和 `design.md` 的 VC 执行。

## 在设计中列出必要路径

在 `design.md` 的 Function Flow 下加 `### 必要功能路径`，列出从真实入口到可观察结果的必要正常和失败路径。每行引用该路径在设计中已定义的 VC。

```markdown
### 必要功能路径

| 路径 | 入口 | 可观察结果 | VC |
| --- | --- | --- | --- |
| FLOW-001 | CLI 收到有效请求 | 输出已保存的记录 | VC-001 |
| FLOW-002 | CLI 收到无效请求 | 退出码为 2，显示诊断 | VC-002 |
```

## 在拆卡前修订计划

对照 `goal.md`、AC、设计和任务依赖，删去次要项并合并重复项。保留实现目标、打通必要依赖或提供验收证据的工作。用 `## 计划裁剪` 记录改动及理由。全部保留时说明各项的必要性。用 `## 保留任务` 表列出本期实际要拆卡的任务和产出。

```markdown
## 保留任务

| 任务 | 产出 |
| --- | --- |
| T-001-save | CLI 保存记录和对应验收 |

## 闭环覆盖

| 验收项或路径 | 保留任务或已有能力 | VC |
| --- | --- | --- |
| AC-001 | T-001-save | VC-001 |
| AC-002 | existing: evidence/invalid-request.md | VC-002 |
| FLOW-001 | T-001-save | VC-001 |
| FLOW-002 | existing: evidence/invalid-request.md | VC-002 |
```

每条 AC 和每条 FLOW 各写一行。多个任务或 VC 用英文逗号分隔。已有能力先做最小验证，把命令和观察结果写到 key 的 `evidence/` 下，再引用该文件。PM 核对任务能否实际完成链路，以及设计是否列全了必要路径。程序核对覆盖和引用。

交互式 PM、autopilot 和命令行 `python <AgenticTask 脚本目录>/advance_phase.py <key> tasks` 共用 AgenticTask 原生门禁。Autopilot 收到原生闭环缺口后进入 L2 修复。通过后进入 `TASKS`，按保留任务拆卡。升级 MW 时同步更新 AgenticTask 脚本及项目安装副本。

已经处于 `PLAN` 的旧计划可在推进前补齐这三节，并在已有功能流中补列必要路径。需要改变已经锁定的 AC 或 VC 时，沿用现有重开流程。
