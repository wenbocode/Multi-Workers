# UE Editor 界面开发

先读项目中最接近的 Editor 面板，确认入口、引擎版本、现有 Slate 样式、术语和状态来源。写代码前，用一份简短的文字布局列出默认可见区块、每块的关键字段以及成功和失败各自影响的操作。可参考 [布局实例](references/layout-example.md)。

## 布局

- 按用户完成任务的顺序排列。配置和测算类页面可从「标题与状态摘要 → 对象与输入 → 草稿 → 结果与对比 → 保存或应用」起步，按任务取舍区块。列表工具把筛选和主列表放在前面，单步对话框把决定和确认放在一起。
- 同级页面复用项目的导航方式。主内容用一致的左边线、字段列宽和分组间距。短输入按内容定宽，长对象名和表格按可用空间伸缩。区块高度随内容增长，窄窗口允许换行、换行排列按钮或滚动，确保关键操作可达。
- 一条短状态摘要回答「现在是什么情况」。把判断所需的值放在主区，用明确标签区分草稿、建议、已保存、当前生效等确实存在的来源。让可比较的值对齐，明确单位，用文字表达未知或未设置。
- 刷新靠近输入，采用建议靠近结果，保存与应用靠近操作结果。按钮名称交代目的地或副作用。将完整路径、原始标识和调试参数放在默认折叠、可复制的诊断区。工程师可展开定位，主流程保持可扫描。
- 沿用当前项目的 Editor 样式与布局约定。检查目标引擎源码及现有控件用法。当前版本支持时，优先使用 `FAppStyle` 和现成 Slate 控件实现数值、对象选择、折叠区和键盘交互。保持焦点可见、Tab 顺序符合阅读顺序，状态可通过文字识别。

## 成功与失败

- **成功**。显示实际完成的动作及结果。预览、采用草稿、保存、运行时应用分别使用对应的完成文案。用户可复核时，展示受影响对象和关键变更。
- **失败或不可用**。在受影响的对象、字段或操作旁说明最短原因及可执行的恢复动作。保留仍有效的输入和历史结果。旧结果标为上次成功或已过期。根据每个操作自己的先决条件决定可用性，例如目标只读仍可允许预览。
- **需要时补齐其他状态**。异步工具显示执行状态和可用的取消动作。空列表说明怎样得到内容。发生部分成功时标明已完成项和失败项，并给出重试范围。

## 验收

默认先提交人工验收。提供正常入口、实现的布局、成功和失败的复现步骤及预期结果，以及已有的预览图、编译或交互证据。请评审者确认关键信息是否一眼可读，状态归属是否明确，失败原因和恢复动作是否清楚，以及窄窗口内关键操作是否可达。记录评审结论和待验证项。

在项目要求或用户安排真实 Editor 验收时，用目标 UE 版本从正常入口复现成功态和失败态，提交相同窗口尺寸和缩放的截图，并检查项目支持的窄窗口。附入口、测试数据、步骤和实际结果。把人工布局评审和 Editor 中实际观察到的行为分别记录。
