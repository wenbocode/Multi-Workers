### B. AC-012 端到端（新建 `test_worktree_e2e.py`）

3. 夹具（全在 `%TEMP%`，链目标必须在夹具内）：
   - `<root>/main/` = **真 git 仓库**：`git init` + 一个提交（至少含 `packages/x/f.txt` 与 `package.json`，让 `git worktree add` 与 lockfile 逻辑有东西可看）；`<root>/main/node_modules/real-dep/index.js` 作为链目标；另加一个**未登记**的 `<root>/landmine/wt2/node_modules` 链指向 `main/node_modules`（域 (c) 的正向语料）。
   - `<root>/wt/` = 用真实流程建的 worktree。
4. **建链走新流程**：`mw worktree add --link-deps`（真实 CLI `python mw.py worktree add …`，cwd = 夹具仓库）。**若不 `--link-deps` 也会触发 npm 注水，则改用 `worktree_cmd` 的 DI 面并把 `npm_hydrate` 注入为 `lambda _: False`** —— 本任务**禁止**跑真实 `npm install` / `npm ci`（AGENTS 硬规则），报告里写明你走的是哪条路。清理走真实 `mw worktree rm <wt>`（rm 不需要注水）。
5. **主树零变化（机器判据，AC-012 的核心）**：清理前后各取一次 manifest = 夹具主树**已跟踪文件**（`git ls-files`）+ 每个文件的 `size` / `sha256` / `mtime_ns`，另加链目标 `node_modules/real-dep/**` 的内容哈希。断言：清理后 manifest **逐字段完全一致**（排序后比较；`.git/` 与 `.mw/` 不在判据内 —— 前者是 git 自身元数据、后者是注册表落点，二者合法变动，报告里要写明这个界定）。
6. **无 block 误放行（用事件序证明，不靠感觉）**：走 DI 面注入记录器，包装 `git` 与 `unlink`：
   - 每次 `git` 调用记 `("git", argv)`，**并在回调内当场断言 `os.path.lexists(<wt>/node_modules) is False`**（即 git 执行 `worktree remove --force` 的那一刻链**必须**已摘 —— 这是"零误放行"的最强形式）；
   - 每次 `unlink` 记 `("unlink", path)`；
   - 断言：`worktree remove` 事件**晚于**最后一次 `unlink` 事件；`unlink` 恰好覆盖 `snapshot_workspace_links`（`worktree_cmd.py:180`）枚举出的链；注册表条目在事务后消失。
7. **正向对照（证明夹具能复刻事故，AC-013 反向对照同源）**：另建一份夹具，用**裸 git** 造 worktree（`git worktree add`）+ `cmd /c mklink /J` 造链，然后跑**裸** `git worktree remove --force <wt>` ⇒ 断言主树 manifest **出现 `removed` 项**（已跟踪文件确实被删）且链目标内容被删。这条证明"零变化"不是因为夹具太干净而空过。**绝不允许对真仓执行任何此类命令。**
8. `mw doctor` 面：清理完成后 `python mw.py doctor --project <main>` 的 `worktree_links` 计数为 0；带 `--worktree-scan-roots <root>` 时**只**报那条未登记的 landmine（`scan-root-leftover`），不报 `wt`（已被 rm 摘链）。
9. 回收：登记在 `finally`/`afterEach`：先 `cmd /c rmdir <link>`（无 `/S`）摘链，再 `rmdir /S /Q <root>`。夹具内 `git worktree remove` 只允许出现在**正向对照夹具**里。
