## 残留与未验证

1. **真实 CLI 子进程无法指向夹具（非 D-12 范围的生产面限制，交回 PM）**：`packages/multi-workers/mw.py:4502` `_repo_root()` 返回 `_SCRIPT_DIR.parent.parent`，即**安装脚本所在仓库**，与 `cwd` 无关。因此 `python mw.py worktree add|rm …` 永远对真树跑 git，`--project` 只影响注册表落点（`worktree_cmd.cmd_worktree` 的 `project_dir`），不改变 `repo_root`。卡片要求「真实 CLI，cwd = 夹具仓库」，在本机上等于对真树执行 `git worktree add/remove` —— 禁止项。故本任务建链/清理都走 `worktree_cmd.cmd_worktree(..., repo_root=<fixture>, git=<recorder>, npm_hydrate=_forbidden_hydrate)` 这一 DI 派发面（CLI 实际调用的同一入口，仅注入依赖）。`npm_hydrate` 注入为硬失败，全程未跑 `npm install`/`npm ci`（且 `--link-deps` 路径本身不注水）。**建议**：若希望 CLI 可对夹具运行，`worktree` 子命令需要一个显式 `--repo`/从 `cwd` 解析 `repo_root` 的入口；否则 e2e 只能走 DI 面。此为可测试性缺口，未改（超 D-12 范围）。
2. **landmine 路径相对卡片的偏离**：卡片写 `<root>/landmine/wt2/node_modules`；本实现用 `<root>/landmine/node_modules`。原因：域 (c) 是 **depth-1**（`<root>/<worktree>/node_modules`，设计 §5 表 (c) 与 `worktree_doctor.py:_scan_roots_domain` 一致），真实语料是 `%TEMP%\mwvg-t5\node_modules`（扫描根 `%TEMP%`、worktree 目录 `mwvg-t5` 为直接子级）。若保留 `landmine/wt2` 嵌套，`--worktree-scan-roots <root>` 无法命中，直接违反验收项 8。改 depth-1 后 `--worktree-scan-roots <root>` 恰好只报该 landmine（证据 §4）。
3. **卡片「unlink 覆盖 `snapshot_workspace_links` 枚举的链」的口径偏差**：`snapshot_workspace_links`（`worktree_cmd.py:180`）枚举主树 `@earendil-works/*`（步骤 1/4 比较面），被摘链由 `enumerate_reparse_links`（`worktree_cmd.py:155`）枚举。按语义断言（unlink 集 == 冻结链集 + snapshot 前后不变），见证据 §2。未被这一措辞掩盖任何真实缺口。
4. **doctor rc 在裸夹具为 1**：夹具无 serve/proxy/凭证，其它 doctor 段不健康属预期；AC-012/验收项 8 只以 `report["worktree_links"]` 为准。
5. **同一 link 可能被域 (a) 与域 (c) 各报一次**：当注册表条目存在、`worktree` 已消失而 link 仍在时，域 (a) 报 `registry-leftover`、域 (c) 报 `scan-root-leftover`（D-12 用例②即此形态）。这不是误报（link 确实是 leftover），只是重复；D-12 未涉及去重，未改（超范围）。
6. **未验证项**：非 Windows 平台（junction 与 `cmd /c rmdir` 本身 Windows-only，测试 `skipif`）；`--worktree-scan-roots` 的多根/预算截断在 e2e 未覆盖（由 `test_worktree_doctor.py` 既有例覆盖）；`worktree add --link-deps` 之外的分支（默认 npm 注水）未在 e2e 触发（AGENTS 禁跑 npm，且已有 `test_worktree_cmd.py` 覆盖）。
