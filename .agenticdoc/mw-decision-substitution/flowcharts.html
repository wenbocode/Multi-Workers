1. 目标

要点：

  • 四个 dp 有真实调用方：dp1 triage（ui-bridge.ts:1730）、dp2 checkpoint（pm-orchestrator.ts:2602）、 dp3 worker 澄清（worker-mode.ts:3903）、dp25 签收结论（mw decide sign，W9/W11）。其余 21 个 "已注册、可验证、未接线"——wired 与 executor 是两个维度（Python executor 只回显，真实动作在 TS/CLI 侧）。
  • 签收不再是人的阻塞点：.mw/decide.json 的 signoff 缺省 auto → 由 jev 出 continue|narrow|revoke； 不可用或低置信才回落到 agent LLM 推断；disable 表示永不签收、done 门禁不阻塞。
  • state 不由 LLM 组装：TS 生产者 + Python _state_builder，jev 只回答题面。
  • 不做向后兼容：state 字段改名后旧 state 直接 input-incomplete。

2.5 两条入口分叉：直接 run 与决策本 run

决策本骨架由配置生成，不由人/LLM 猜：

decide_registry.json  ──▶  mw decide book new <dp>  ──▶  骨架（键与顺序 == required_state_fields）
                                                          │
                                        人或 decision worker 填值（只写输入，不写预期答案）
                                                          ▼
                                             mw decide book check --book B

七类失败码：book-schema / book-state / book-placeholder / book-context / book-evidence / book-budget / book-secret。

2.6 decision worker 类型的门禁（运行时）

离线预判：mw dispatch check --card FILE [--dp ID] [--book FILE] [--json] （exit 0 干净 / 2 拒绝 / 1 用法错误），判据与 dispatch() 拒绝时完全相同。

2.7 签收链路（mw decide sign --key <任意 key>，W9/W11）

判据（写进 dp25 的 instructions）：

  • continue：N≥1 可用行 + 链闭合 + 每行 timi-decisions/jev-latest/api
  • narrow：能力降级但仍要保留部分授权
  • revoke：链断、engine 不符、或没有任何可用行

防自我背书：dp25 自己的档案行不计入签收事实；signed_via 只写 auto-decide|auto-llm|cli|tui。
