## §0 Goal Alignment

来源：`.agenticdoc/goal.md`（legacy，三节内容已确立）。
- 对齐：使 PM/Worker 协作中的决策可追溯、可观察，降低自动编排黑盒风险。
- GC-1：文件驱动协调，不引入中心化调度器；看板不是新的任务调度器。
- GC-2：通过扩展集成，不修改 pi 核心。
- GC-3：凭证隔离，不泄漏 API key、不开放 worker 额外凭证通道。
- GC-4：共享记录并发写入需使用文件锁和原子发布。
- 冲突：无；本地交互服务的生命周期在 design 比较，不自动绑定 mw serve。
- 预期收益：项目决策来源与实际调用/吸收链可查；DP 测试通过内部真实 Jev 调用且与生产签收隔离。

## §1 功能概述

### 1.1 目标与核心场景
1. 修复窗口 `/mw decide dp list` 的 unknown sub 缺口；Python CLI 与窗口只读入口一致。
2. `mw decide monitor`（窗口 `/mw decide monitor`）打开浏览器独立应用窗口，以非默认高位端口提供当前项目看板。
3. 决策历史页签展示项目经历的全部已记录决策，区分人工与模型来源，以及模型建议、升级、未采纳、实际吸收执行、机器授权维护等状态。
4. 自动决策详情展示决策本、实际调用请求、实际返回、决策吸收与应答，包含失败详情；新增记录需真实采集，不是用摘要冒充原文。
5. 独立 DP 测试页签选择任一注册 DP，生成并填写决策本，校验后真实传给 Jev、观察返回与生产采纳判定/动作预览。
6. 人工来源包括人工回答、覆盖模型结果、授权调整、人工签收；向前补齐对应记录链。

### 1.2 技术与环境
- Python mw 与 TypeScript pi 扩展；浏览器本地交互页面，Windows 为当前主要环境。
- 独立浏览器应用窗口，用户明确选择，不做 TUI 替代交付。
- 端口使用非常规高位端口，只监听 `127.0.0.1`；具体端口选择、占用处理及配置方式由 design 确定。

### 1.3 范围与不做什么
- 补齐全部现有 25 个 DP 的业务输入字段契约；后续新增 DP 也须从注册表获得一致的骨架/校验。
- 测试允许显式人工评估关闭或 P0 DP，但仅观察模型；生产自动门禁不变。
- 测试记录独立保存，可查看，不进入生产决策签收的计数/摘要。
- 不执行测试的真实业务动作，不修改 DP 授权，不新增 act 开关。
- 不恢复从未记录的历史原始请求/返回/决策本；显示“未记录”。
- 不提供远程访问、不引入 Electron 或新的中心调度器作为默认方案；不擅自改共享凭证配置。

## §2 业务约束

### 2.1 真实链路与证据
- 校验、组装、state/questions、传输、结果解析复用内部真实生产能力，不另造模拟或简化网络链路。
- 实际请求/返回在真实传输边界采集，保留脱敏后的发送体与响应原文；重建 payload、归一化答案不能冒充原文。
- 每次调用有独立标识；与决策级标识、重试、决策本版本、吸收/应答有明确关联。调用计数与决策计数分开，保留决策级幂等语义。
- mode=auto、available=true、task.md decision 头均不单独证明实际自动执行。
- 历史推断关联必须标 inferred；缺失来源为 unknown，缺失字段为“未记录”，不能按当前默认值回填历史事实。

### 2.2 安全与隔离
- 非常规端口不是安全控制；本地接口需访问校验，拒绝未经授权的外部网页发送模型请求。
- 认证凭证不得进入浏览器或证据文件；调用/决策本/自由文本/失败输出均需脱敏及 HTML 安全转义。
- 脱敏、截断、采集失败明确标示，不能静默伪造完整记录。
- 测试是人工明确提交后的真实调用，不由页面打开、轮询或自动化测试隐式发起付费请求。
- 测试不写生产授权表、生产 decisions 档案或生产签收事实；仅独立测试证据落盘。
- 生产 disabled/P0 拒绝行为不变；人工观察测试通道需显式来源与仅观察标记。

### 2.3 可观测与异常
- 凭证缺失、非法决策本、上游失败/限流/超时、记录失败、端口占用、应用浏览器不可用须明确展示，不假报成功。
- 浏览器不可用时可提示可用 URL 与安装/选择浏览器方法；普通窗口回退需明确提示，不能冒充独立应用窗口。
- 默认当前项目全 key 历史；支持 key、DP、来源/状态筛选，测试记录不混入默认生产历史统计。
- 响应预算沿用内部配置；不另承诺无证据的耗时指标。

## §3 验收标准（已锁定）

AC-001: 在无 watched key 且项目有注册 DP 时，窗口 `/mw decide dp list` 列出与 Python CLI 相同的 DP 集合，unknown sub 错误数量为 0。
AC-002: 在项目存在人工与模型决策记录时，历史页默认跨 key 展示全部已记录决策，每条显示可证实来源或 unknown，并支持 key/DP/来源/状态筛选。
AC-003: 在新增自动决策完成调用并产生吸收/应答记录时，详情显示决策本版本、实际请求、实际返回、吸收及应答，全部使用明确关联标识，未产生的环节明确显示未记录或尚未发生。
AC-004: 在人工选择 DP 并提交合法决策本时，测试页通过内部真实 Jev 调用返回真实结果与采纳判定/动作预览，真实业务执行器调用次数为 0。
AC-005: 在请求、返回、决策本或自由文本含认证凭证时，浏览器内容与持久化证据中认证凭证原值出现次数为 0，脱敏部分明确标示。
AC-006: 在支持应用模式的浏览器已安装且端口可用时，`mw decide monitor` 与 `/mw decide monitor` 打开独立应用窗口，包含决策历史/DP 测试两个页签，监听地址严格为 127.0.0.1 且端口在设计定义的非常规高位范围内。
AC-007: 在端口被占用、重复开启或应用模式浏览器不可用时，monitor 不终止占用进程、不报假成功，并按设计定义的复用/重选/错误策略返回实际地址或明确原因。
AC-008: 在既有生产签收前后进行任意测试调用时，生产授权表、生产 decisions 档案和既有签收文件字节不变，生产签收计数与 rows_sha256 不变，测试记录独立可查。
AC-009: 在分别选择全部现有 25 个注册 DP 时，测试页生成具备明确类型/说明的业务输入契约骨架，合法填写可通过校验，未知或类型错误字段被拒绝，不以仅身份字段冒充业务输入能力。
AC-010: 在人工提交关闭或 P0 DP 的合法测试本时，模型可被真实调用且记录标为人工仅观察；授权表字节不变，业务动作执行次数为 0，生产 disabled 决策调用仍为 0 次网络请求。
AC-011: 在非法决策本、凭证缺失或上游错误/超时场景下，测试页展示明确失败状态与脱敏详情；非法决策本的模型调用次数为 0，不返回模拟成功。
AC-012: 在同一 key/决策标识产生多次调用及重试时，每次调用独立可查并关联到决策，调用计数不因决策幂等而丢失，吸收状态不由 mode/available/task 头推断为成功。
AC-013: 在历史记录缺实际请求/返回/决策本或仅推断关联时，详情逐项显示未记录及 inferred；未采集原文重建数量为 0。
AC-014: 在人工回答/覆盖/授权调整/人工签收及机器 refresh/自动签收各发生一次时，向前记录保留实际来源与应答/理由关联，机器动作标成人工的数量为 0。
AC-015: 在外部网页、错误来源或缺少访问凭据请求测试接口时，接口拒绝请求且模型调用次数为 0；仅打开看板或刷新历史的模型调用次数为 0。
AC-016: 在真实调用成功、上游拒绝及多次重试场景下，新增调用详情逐次展示实际请求、实际响应或未收到响应原因、模型/传输/耗时/次数等元数据；脱敏、截断或采集失败均有明确标记。
AC-017: 在窗口尝试透传 `dp on/off/set/apply` 或测试提交夹带执行/授权修改参数时，monitor/只读窗口入口拒绝该操作，授权表写入次数和测试业务动作执行次数均为 0；既有人工 sign 流程不被替换。

## §4 风险与研究依据
- RQ-1：窗口 parser 仅 show/sign；dp 只读分流需先于 key 解析，通用透传会绕守卫。`evidence/research/spec-command-entry-20261022.md`。
- RQ-2：历史只存 digest/归一化答案，原文和决策本无法恢复；dp1 同 key 调用折叠；吸收及人工生产记录缺口。`evidence/research/spec-decision-trace-20261022.md`。
- RQ-3：HTML 仅静态资产，交互接口需新增；测试默认 run 存档污染签收；21 DP 业务契约缺失。`evidence/research/spec-dashboard-playground-20261022.md`。
- 调研冲突处置：RQ-3 称 settle 无生产 writer，但 RQ-2 给出 pm-orchestrator.ts 的明确调用证据，不采纳 RQ-3 此条；design 重新核对。
- 用户最终确认见 key-decision.md：独立浏览器应用窗口、非常规端口、测试独立记录、全 DP 契约与 P0/关闭 DP 人工观察。
- 待 design 决定：端口范围及占用策略、浏览器探测/回退、服务生命周期、记录 schema/锁、生产全部写入点、测试独立权限与配置、输入契约闭集、传输保真与记录失败策略。
