### 3.3 "N≥4 时 tick stall 是否可接受"（量化回答）

- 单次 `advance` 是**同步 `subprocess.run`**（一次 Python 冷启动 + 门禁脚本），实测
  **约 0.2–0.8s**，是一次空 tick（~3ms）的 **~2 个数量级**；对单个 key 而言，tick 墙钟里
  advance 占比 `window_share ≈ 0.99`。
- 但 `advance` 的调用点是**每 key 每 tick ≤1 次**，且 N 个 key 的 advance 在 tick 内**串行**
  （同步 subprocess）。按实测中位数外推：N=4 时 tick 内 advance 串行合计 ≈
  `4 × 0.2–0.8s = 0.8–3.2s`，接近但通常不超过默认 `poll_interval_sec=4`；N≫4 或多个 key 同 tick
  撞上 phase 边界时会顶到/超过 poll 间隔。
- 判定：**当前 N≤4 量级可接受**（单次 advance 相对空 tick 是主导项，但绝对墙钟仍在 poll 间隔内）；
  **若生产实测出现同 tick ≥4 次 advance 并发撞车，应上独立执行器（D-107）**。本卡的职责是把墙钟
  打进 `advance` 事件的 `data={"ms": n}`（M-02 已落）并给出原始样本，优化与否按 D-107 留待实测。

## 4. AC-002：顶配（top-up）空窗量化（只量化，不改代码）

### 4.1 原始输出

语料：1 个 running key + 6 张无依赖互不重叠写面卡，per-key 上界 4。

```
[VERIFY] AC-002 batch1_started=4 batch1=['ap-k1-T-1', 'ap-k1-T-2', 'ap-k1-T-3', 'ap-k1-T-4'] per_key_bound=4
[VERIFY] AC-002 straggler_ticks=2 free_slots=3 idle_slot_ticks=6 straggler_tick_ms=[5, 4] batch_boundary_tick_ms=13
[VERIFY] AC-002 next_batch_started=2 next_batch=['ap-k1-T-5', 'ap-k1-T-6'] ticks_after_all_terminal_to_next_batch=1
[VERIFY] AC-002: batch1_started=4 topup_window_ticks=2 free_slots=3 idle_slot_ticks=6 next_batch_started=2 extra_idle_ticks_at_batch_boundary=0
```

### 4.2 实测含义

1. **批内 min 恒等成立**：tick 1 实起 `min(4, 6) = 4`。
2. **顶配空窗（核心）**：把 T-1/T-2/T-3 置 `done`、T-4 留作 straggler 后，连跑 2 个 tick
   **0 新派发**（断言 `new_rows == set()`）——因为 `orchestrate` 的
   `if key in in_flight_keys: continue`（key 内尚有一行在飞即整 key 跳过 `_advance_key`）：
   **释放的 3 个槽位不被补派**。`idle_slot_ticks = 3 slots × 2 ticks = 6`。
   空窗时长 = straggler 的**剩余 runtime**（本 fixture 用 tick 边界精确控制 ⇒ 2 tick 回合）。
3. **批次边界不额外空 tick**：T-4 终态后的**下一个 tick** 同一 tick 内即派出下一批 2 个
   （`ap-k1-T-5/6`），`extra_idle_ticks_at_batch_boundary = 0`。
4. straggler tick 墙钟 `[5, 4]ms`、批边界 tick `13ms`（均为无 advance 的空 tick 量级）。

### 4.3 判定

- **当前 tick 驱动语义下，可接受**：默认并发下同一批 worker 是**同一 tick 同时派发**的，等长 runtime
  时整批几乎同时终态，批次边界额外空 tick = 0，makespan 与"持续补派"无差（`ceil(M/N)` 批 vs 流水线在等长
  runtime 下相同）。
- **唯一损失面 = runtime 方差的尾部**：一个长尾 worker 会让最多 `cap-1` 个槽位在它的剩余 runtime 内
  空转（实测：3 槽 × 2 tick = 6 slot-ticks）。这是**有界**的，且不丢任务（下一批照常）。
- **结论**：不需要为此在本 key 开顶配；若后续生产实测 worker runtime 方差大（有 straggler 长期占位），
  再评估"跨 tick 补派"作为独立改进项。**本卡按卡文只量化，未改 `orchestrate`/`execute_loop`**。
