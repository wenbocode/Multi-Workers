# Research: spec-decision-space（决策空间与备选方案）

日期: 2026-09-25 · 作者: PM

## 目标重述

让「reviewer 表达 FAIL 的所有自然形态」都触发 below，同时不在 PASS 报告的 FAIL-相邻文本上误伤（false positive），且不动存量判定语义。

## 备选方案

### 方案 1：加宽正则（在现 `_L3_FAIL_RE` 上扩展形态）

- 做法：`\|` 前缀放宽为「行内任意位置/行首项目符/散文行」，如 `r"(?:\|\s*\**|-\s*\**\s*|^\s*|—\s)FAIL\b"` 一类组合。
- 优点：改动面最小（一行 + 用例）。
- 风险：散文/行内任意位置的 `FAIL` 会命中否定语境（`FAIL 行 0`、`0 FAIL`、`无 FAIL`、`no FAIL`、`failed=0`）与元话语（「若 FAIL 则重跑」）；needs-rerun 行的从属关系（`needs-rerun：9` 独立成词不含 FAIL，但 `- **FAIL：n**` 与 needs-rerun 常同行）。误伤方向 = 把真 PASS 判 below ⇒ 制造 stalled + 人工闸门，损失面回到「时间税」。
- 结论：可行但必须配否定语境豁免表；豁免表本身要语料驱动（design 阶段 RQ）。

### 方案 2：结构化检测（只扫「结论承载面」）

- 做法：FAIL 判定只在结论承载节/行上生效——`## Quality Gate Report` / `## Achieved` 提取节内 + TL;DR/汇总行（`_md_section` 已有提取机制）；或表格单元格 + 以 FAIL 开头的项目符/汇总行（`^\s*[-|]\s*\**\s*FAIL`）。
- 优点：天然排除元话语与正文叙述（如「Changed Files」里描述测试失败的散文）；与现有节提取机制同构（复用 `_md_section`）。
- 风险：TL;DR 不在两节内（sampling 的受害行就在 TL;DR）⇒ 扫描面要显式含 TL;DR；提取边界坑（P-013：节内 H2 截断——判据与提取边界必须一起想）。
- 结论：方案 1 的收窄版，方向更稳。

### 方案 3：提示词侧钉机器行（`VERDICT: FAIL` 协议行）

- 做法：L3 prompt 要求输出一行机器可读裁决（如 `L3-VERDICT: PASS|FAIL`），解析优先读协议行，文本 FAIL 扫描降级为兜底。
- 优点：判定与表达解耦，最根治。
- 风险：**存量 reviewer 不会立刻遵守**（prompt 变了但行为随机——A-03 的教训：产出位置随机），兜底扫描仍必须是全形态 ⇒ 本方案不消灭 P0 需求，只是叠加；且涉及 prompt 面变更，影响所有新派发轮次。
- 结论：作为 design 阶段可选项评估，不阻塞 P0 主线；若做，协议行缺失时走方案 2 的扫描。

### 方案 4：双段检测（cheap scan + confirm）

- 做法：宽正则先命中，再对命中行做否定语境排除（`0 FAIL`、`FAIL 行 0`、`无 FAIL` 等白名单模式）。
- 优点：召回与精确解耦，每段都可单测。
- 风险：白名单是枚举式的，新否定写法（`zero FAIL`、`FAIL-free`）会漏 ⇒ 豁免表要留扩展位并语料回归。
- 结论：与方案 2 组合（结构面 + 否定豁免）是当前倾向。

## 倾向（进 design 阶段验证）

**方案 2 + 4 组合**：结构化扫描面（两提取节 + TL;DR/汇总行 + 表格/项目符形态）+ 否定语境豁免表，全部语料驱动（真实事故样本逐字回放为验收）。方案 3 记为后续可选增强，不进本 key。

## 硬约束（沿用户既往裁定）

1. fail-closed 方向不变：宁可 below（损失时间）不可 false-meets（污染事实面）——但误伤本身也是损失，豁免表必须有语料证据。
2. 判定语义组合不变：source fallback 两源一致、缺节仍 below、verdict 记录不代写（PM/QG 转写路径不动）。
3. 框架源码不引入工程词表——FAIL/PASS 是框架自身协议 token，不属于工程词表，无冲突。
4. 存量绿测试零回归（source-fallback/freshness/closure-repair/e2e 全链）。

## 开放问题（design RQ 输入）

- 扫描范围现状：FAIL 扫描是全文还是提取节？（RQ-1）
- 否定语境的真实语料面有多大？（RQ-3）
- mvp-closeout 38 处朴素 `| FAIL` 的轮里是否也有否定行（双重命中/误报互作）？（RQ-3）
- below 判定的留痕粒度：现 reason 是否足以区分「FAIL 命中」vs「缺节」？（RQ-1）
