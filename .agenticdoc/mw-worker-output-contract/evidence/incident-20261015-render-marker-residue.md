# 事故记录：渲染标记残留与控制字符混入（2026-10-15）

## 现象

T-09 结案期间的 PM 可见消息里出现两类残留：

1. **`<# ... :#>` / `<# ... </#>` 块**：出现在 PM 工具调用前的「引导说明」位置（如
   `<# update FW-001 + FW-009 status:</#>`），呈成对标记包裹一句中文说明。用户反馈
   「之前没有发生过」，并要求追查与当前修改的关联。
2. **控制字符混入文档**：`_pitfalls.md` 追加的 P-037/P-038/P-039 三条记录中出现
   `\x07`（BEL）×2、`\x08`（BS）×1，具体位置：
   - `\x07chieved.md 遗留 5`（P-037 关联行，`achieved.md` 的 `a` 被 BEL 替换）
   - `\x08ash 事件`（P-038 事实行，`bash` 的 `b` 被 BS 替换）
   - `\x07chieved.md 遗留 3`（P-039 关联行，同 P-037）

## 根因分析

两类残留发生在同一时间段（T-08/T-09 收尾，工具调用密集），但性质不同：

1. **`<# ... :#>` 块**：消息生成层的注释/折叠标记残留。仓库与 pi 扩展代码中均无此
   语法，说明它不是项目或 pi 渲染器的既有语法，而是消息层在生成「工具调用前置说明」
   时产出的包裹标记，未被隐藏层吸收而直接显示。**未进入任何文件内容**。
2. **`\x07`/`\x08` 混入**：`_pitfalls.md` 追加通过 bash 工具 + Python heredoc 传输。
   被替换的均为词首字母（`a`/`b`），`\x08`+`ash` 在终端里回显近似 `bash`，呈
   「转义序列剥离后遗留字符」特征——与消息层标记残留同源的传输/编码扰动，间歇性，
   3 字符/1 文件，不可确定性复现。

共同触发条件：同一会话内多次「bash 工具 + 多行 heredoc/引导文本」传输。此前未发生
的原因：本 key 前期文档写入多以 `write` 工具完成，本次收尾改用 bash heredoc 追加，
暴露了传输路径上的偶发扰动。

## 影响

- 聊天可见消息：纯噪声，无功能影响。
- `_pitfalls.md`：3 个字符被替换（均已还原），语义完整，无内容丢失。
- 其它 PM 文档：无混入（逐文件复扫确认）。

## 修复

- `_pitfalls.md` 控制字符清零（本记录提交前完成，复扫 NONE）。
- 后续 PM 文档写入统一使用 `write` 工具，不再用 bash heredoc 写文档。

## 预防规则（追加到 _pitfalls.md / P-040）

1. 任何文档写入后先跑控制字符扫描 + `git diff` 核对，再继续下一步。
2. 可见消息不出现 `<# ... :#>` / `<# ... </#>` 包裹标记，工具调用前置说明用纯文本。
3. 多行文本写文件一律用 `write` 工具；bash 仅用于只读命令与脚本执行，避免 heredoc 写文档。
