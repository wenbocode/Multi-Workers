## §0 Goal Alignment

来源：[项目goal](../goal.md)，三段内容已确立的存量项目目标。

- 对齐：提高PM/Worker协作中决策材料的有效性、原角色接回与可验证交付，避免单选退化及上下文噪音。
- GC-1：不新增中央调度/授权服务，复用项目文件、既有队列、锁和原预算。
- GC-2：通过MW扩展与Python后端接入，不修改pi核心；现存其它任务的核心例外不扩展到本key。
- GC-3：保留Worker进程/工具隔离、原任务read_scope/deny_globs/write_face和凭证隔离。
- GC-4：PM组织与回收、实际Worker自评、独立review和正式业务唯一writer分别保持真实身份。
- GC-5：原事项时间/次数/字节/模型额度跨准备、等待与返工连续，不因新卡或时间戳刷新。
- 冲突：当前未识别原则冲突；未来实施前必须核对活跃continuity和决策源码，不把旧文档当源码审计结论。
- 预期收益：固定候选不再缩为一个，必要正文和定义实际入模，单wire恢复全部原因，原始返回可直接找到；分别由AC-001、002、005、010、012验证。

## §1 功能概述

### 1.1 目标

为八个DP建立统一但职责独立的材料准备、来源追溯、请求投影、合法单选配对、反解与原主体接回链。将本地决策本、实际模型完整payload、原始返回和真实业务检查明确分离。以“达意”减少噪音，不以提高confidence作为质量标准。

### 1.2 技术与环境

沿用Python MW后端、TypeScript agent-team-loop扩展、现有timi/jev单选传输和本地文件证据。开发目标工作区为E:/gitlite/Multi-Workers；Windows为当前验证环境，平台约束沿用仓库AGENTS。原文/相对引用保留在本key docs/。

### 1.3 用户场景

- S01：PM选择Worker类型或组织剩余工作，发送目标/偏差/实际操作和资源，保留完整候选。
- S02：实际Worker判断继续、有界补证或如实结束本run，助手不代其自评。
- S03：PM已有同版本独审，逐AC/VC核质量；签收读取当前同对象/范围QG，而非借用其它产物结论。
- S04：原主体比较当前现场方案，能看到来源目标优先级、区分证据、有界后继和停止条件。
- S05：复杂材料委托可指定模型的prepare Worker，原主体吸收；简单材料允许直接准备。
- S06：文件只给路径或内容超限时，准备方取正文并有来源压缩，保留失败/未知/完整覆盖。
- S07：模型返回一个fix配对，PM能恢复多个原因/剩余项，再按原权限执行。
- S08：用户/值守窗口回看完整请求、单选选项、完整原始返回、反解与本地/业务检查。
- S09：准备失败、模型关闭、来源漂移、超时或取消时，按原continuity回收且不刷新原预算。
- S10：[REVISED 2026-11-19 用户澄清] 以v0.5已有八DP样例作范本，完整串起本地决策本、实际模型输入、真实原始回包与PM参考裁定，给开发理解/对比/校验；不以未来八次真实采集代替该交付。
- S11：[REVISED 2026-11-19] 对照原版八份和整合优化auto的版本/事实差异，核字段/候选/原因恢复与PM接回语义；原实验没有历史生产PM记录时明确标当前参考裁定，不伪造派发结果。

### 1.4 范围

实现范围：八DP专属数据合同；文件正文/追溯/压缩；desc和引用/术语；固定候选/原因配对；prepare隔离与状态守卫；QG/sign前提；auto可区分性/路径；冻结/去重/反解/业务复核；monitor回放。

不包含：修改项目目标/AC或授权、长期并行兼容任意旧协议、修改pi核心、真实业务代验收、无授权构建安装/发布、凭证配置变更、全仓历史故障清理。历史真实API响应不改，本轮不调用任何模型。

## §2 业务约束

1. 固定候选：w-type四类、steer四类、w-check三类、QG pass/fix/reopen、gate四类、sign三类、route七入口；auto为2..5真实不同路径。合理候选不可因缺推荐依据删到一个。
2. QG必须先有当前独立review并完成逐适用AC/VC核对；核对完成不等于全部通过。sign必须带当前同对象/范围/版本QG、目标和偏差。
3. `desc` 最多 10 句，固定本地预算 1000 单位。按原字符拼接 `desc` 数组，以一个 LF 分隔各项，每个非 ASCII Unicode 码点计 1 单位，全部 ASCII 码点按每 4 个计 1 单位并向上取整。发送前在宿主完成，计量与模型和网关无关。
4. 文件路径/hash不能代必要正文；大材料须有来源压缩，失败、反证、未知、AC覆盖、合法候选判据不丢失。
5. 一次模型请求只有一个decision_selection单选题，wire通过同版pair-map恢复业务结论和多个原因；不另发理由题。
6. 本地身份/账本/准备日志/actionplan/作者预期不能整体入模；必要业务约束、来源正文和术语定义须实际可见。
7. 准备模型与决策模型分离；准备助手无任意shell/网络/产品写入/决策密钥/claim/QG/sign写权限。
8. source/候选/范围/revision变化要重验；时间戳变化不能制造新事项或新的调用额度。
9. 不承诺任意远端响应时延或confidence下限；性能按既有原预算和步骤上限可判定，不能另造资源授权。
10. 本需求细节依据[evidence/research/spec-baseline-20261119.md](evidence/research/spec-baseline-20261119.md)，无外部资料假设。

## §3 验收标准

编号首次分配后保留。以下为未来实现验收，不表示当前已通过；AC-001—014对应docs原DPA同序映射，AC-015—018为用户澄清后的v0.5四段范本及逐项对比验收要求。当前draft未伪造用户AC锁定。

| 编号 | 验收标准 |
| --- | --- |
| AC-001 | 在固定DP或auto准备发送时，候选校验器保留该DP完整业务闭集、QG含pass/fix/reopen、auto含2..5真实不同路径；缺固定项或只剩一个候选时network_attempts=0并返回具体缺项。 |
| AC-002 | 在必要材料含文件引用或超限正文时，实际payload包含所需正文/有来源摘要；仅路径或丢失失败/未知/逐AC覆盖/候选判据时发送次数为0并返回来源级缺口。 |
| AC-003 | 在 PM 和 Worker 正常决策入口对 desc 应用同一发送前本地预算规则。最多 10 句且本地计数为 1000 时可发送，超过 10 句或本地计数为 1001 时拒绝，决策网络尝试为 0，并给出 desc 字段诊断。计量无需访问 Timi。 |
| AC-004 | 在任意DP完成请求投影时，所有模型可见叶子字段都有来源/变换/发送落点；本地身份、准备日志、actionplan、作者expected均不作为整体state透传。 |
| AC-005 | 在请求引用AC/VC/发现/工作项/入口、缩写或业务代码时，body内各引用均有当前适用正文或解释；悬空、同ID错对象、冲突定义在发送前检出并给字段路径。 |
| AC-006 | 在QG缺当前独审/漏AC或sign引用过期、错对象QG时，前提检查返回needs-review/needs-evidence或stale且不形成正式pass/finalize；合法输入逐项保留fail/not-run/unknown及全部未关闭项。 |
| AC-007 | 在prepare工具越序、越范围、换模型未记录或旧revision发布/吸收时，host拒绝动作且产品写入/认领变更/越权读取均为0；合法同版流程从bound到absorbed可回放。 |
| AC-008 | 在auto有n个候选时，可区分性报告覆盖n×(n−1)/2个无序对；缺关键偏好或方案等价分别返回needs-evidence/equivalent，不新增假业务候选或私删合理候选。 |
| AC-009 | 在auto路径含循环、无停止、重复次数或全程超原预算时，路径验证/执行前检查拒绝该路径；合法路径每步有条件后继、信息价值、上限和终止出口，原次数余额不增长。 |
| AC-010 | 在收到本次合法fix wire时，按该次revision恢复choice/basis_id及全部finding_ids/remaining_ids；未知wire、错revision、遗漏原因不能产生business_accepted=true。 |
| AC-011 | 在同事项重复准备、仅prepared_at变化、并发提交或已发未获完整响应时，既有去重与账本保持单一原matter，等价请求network_attempts不增加，transport-unknown不盲目补发，原预算无重置。 |
| AC-012 | 在一次请求返回或失败后，记录分别保留本地材料、Request.data原字节、响应原字节/id/usage、解码/业务检查/执行状态；monitor有直接原始返回入口，展示内容与捕获逐字节或等值校验一致。 |
| AC-013 | 在DP关闭/不可用或prepare失败时，原PM/实际Worker沿既有continuity在原权限/预算内接回；新增用户审批数为0，不强制全局等待，不发生PM代Worker或助手代独审。 |
| AC-014 | 在声明生产接入完成前，全部AC有当前源码/当前spec绑定的必要定向验证和另一执行者独立复核；未运行/失败/历史基线均如实记录，历史合成API实验不能标为本key实现通过。 |
| AC-015 | [REVISED 2026-11-19 用户澄清] 在提交开发范本时，v0.5全部八DP均可按决策本→实际完整payload→真实原始返回/同版反解→PM参考裁定四段读取；原版八份和优化auto对照共9个唯一案例，四段参考覆盖8/8，原始输入/响应与来源字节一致。 |
| AC-016 | [REVISED 2026-11-19] 在对比范本时，两个八DP版本组合明确列出，模型ID/usage/来源hash/候选映射不可串版；PM参考解释采纳或退回、保留原因、后续工作/原检查及禁止错误声明，事实变更不被称为同事实confidence提升。 |
| AC-017 | [REVISED 2026-11-19 逐项复核] 实现验收须按reference-comparison-contract.md输出9例×4段共36行对比，每行有原件回放和当前实现观测、逐字段基准/当前值或证据指针、规则/结果/差异依据及AC/VC；wire/basis/全部原因严格核对，PM核处置/理由/后续/必要事实/禁止声明。已知QG及旧auto负例检出；缺行、错版、原因丢失、无依据差异、未验证或假执行均不通过。 2026-11-22 澄清：旧 `dp-auto` 历史回执为空时，保存历史缺失事实。第四段验收采用当前 PM 正常入口复跑同一负例后的接回记录。记录须与本次发送前拒绝事件和当前 PM 身份关联，列出具体理由和下一步，核实模型调用为零、业务动作未执行、原权限及余量未扩大。证据齐全时第四段记 `expected-rejection`。 |
| AC-018 | [REVISED 2026-11-19] 在使用四段范本时，前三段历史保存记录与本次PM参考裁定有明确来源性质；缺失的历史生产PM采纳/派发/writer仍为null/未执行，不补造；本交付不要求新API/新派发，额外真实采集不得作为该范本完成前置。 |

## §5 记忆前馈

### 可复用资产

项目_arch_snapshot已有材料诊断/生成注册表、DecisionConfig/Timi后端、PM decision-tool/triage-client、原预算/身份/continuity、任务卡model选择、Worker读写面和faux/suite测试能力。复用这些通道，不另建中心服务。具体入口在design中限定为候选位置，实施前读完整源码。

### 需规避坑点

- P-001：UTF-8原件使用字节复制/显式UTF-8，不做PowerShell读改写编码往返。
- P-003：先生成完整内容再写；有并发读取时原子发布，不能以空文件编译成功当验证通过。
- P-005：每个新字段明确谁写、谁读、缺失怎样处理；至少一条真实生产写入链的离线测试，不能只手写fixture。
- P-006：证据日志须实际在测试原始输出可见，不只信退出码。
- P-007：独立复核卡采用受限报告落盘通道，复核者与实现者分离。
