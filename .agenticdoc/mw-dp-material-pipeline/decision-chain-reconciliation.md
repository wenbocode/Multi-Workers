# 八个 DP 的同次对账

按已有 AC-012、AC-014、AC-015—018 和 [v0.5 四段对照合同](reference-comparison-contract.md) 验收。目标是从任意决策或回执查回同一次的决策本、请求、原始返回与原主体接回。对照表仍是九例、36 行。接回和回执在第四段分别取证，使用各 DP 已有的生产入口。正式 key 签收适用 dp-sign-key。

## 四段关联规则

| 段 | 必须能查到 | 核对方式 |
| --- | --- | --- |
| 决策本 | 本地材料、来源、版本、最终合法配对及冻结摘要。 | 从真实宿主取得项目、key、DP、事项/任务绑定和具备责任的角色。由本地逻辑 ID 或现有可信绑定找到冻结本。 |
| 决策模型调用 | 实际尝试的 Request.data、完整单选、请求摘要和传输状态。 | 由真实调用记录关联 `decision_id` 或 `logical_id`，单次传输按 `call_id + attempt_index` 配对。测试以实际请求字节核对生产投影。 |
| 原始返回与反解 | 对应尝试的 response、API id/usage、选中 wire 及本地反解。 | 按同次冻结配对还原 choice、basis、全部原因与剩余项。接受或执行须核当前来源、事项与版本。API 响应 ID 仅作提供方侧证据，宿主关联使用本地绑定。 |
| 原主体签收/接回 → 回执 | 谁接回、接受或退回了哪一份结论、实际做了什么，何时写入或拒绝。 | 接回关联同一 `decision_id` 或真实 `local_ref`。按适用入口追到独立 writer 证据及 `event_id` 或正式产物引用。动作结果与回执写入结果各有状态，可以从回执反查来源链。 |

关联必须能回到原记录。缺任务绑定时保留空值。已经存在的逻辑 ID、调用 ID、事件 ID 和原产物引用可按记录里的真实关系对账，不能靠相近时间、相同 key、相同 choice 或文本相似补链。切换窗口或重放时重用已确认回执，核有无新增合法动作。回执写入失败保留已经观察到的业务结果，先对账再决定是否重写记录。只接受已有入口的授权与幂等规则。

在完整离线捕获中核请求和响应字节。生产记录发生脱敏、截断或保留期清理时，按安全副本、原摘要及完整性标记核验，对缺失的字段明确标记，不能只用摘要给内容判通过。

## 八个 DP 的第四段应查什么

| DP | 接回主体与检查 | 最小收口证据 |
| --- | --- | --- |
| dp-w-type | 原 PM 按选型结果或本地判据核任务卡、能力、写面及真实派发条件。 | 选型来源与结论。若实际派发，核同任务卡的派发 writer 或队列回执。只选型时保留未派发状态。 |
| dp-pm-steer | 原 PM 核结论和全部理由，明确是否进入收窄、拆卡、接手或上抛。 | 实际重规划/apply 或相应动作的回执。只准备方向时保存接受或退回及未执行状态。 |
| dp-w-check-task | 实际 Worker 核可达性和本次期限，PM 可读取其记录。 | 自评接回、真实补证或终止的记录及同一次 run。未实际读证时保留未知。 |
| dp-QG | 原质量入口按当前对象、版本、独审与逐适用 AC/VC 接收或拒绝。 | 质量结论及全部未关闭原因的正式记录或拒绝。后续修复派工按实际发生另核。 |
| dp-gate-approve | 实际 gate handler 核 gate ID、项目、key/阶段、授权及动作范围。 | gate 的授权状态和适用的 effect 回执。仅有选项或建议时不得把 effect 写成已发生。 |
| dp-sign-key | 原签收入口核当前独审、合同、产物、未完成项及审批。 | 既有正式签收 writer 的写入或复用回执，或真实继续、拒绝记录。只有适用的 finalize 才查 `sign-final.md` 及既有验证结果。 |
| dp-auto | 原 PM 核选中路径、条件、原预算与停止事实。 | 实际动作和首个可观察结果，或未启动/停止记录。后续探针与执行各自绑定其真实结果。 |
| dp-route | 原 PM 消费明确路由和适用范围，再由目标入口核它自己的条件。 | 路由接收或退回记录。有后继请求时关联真实后继 ID，只有路由时保留未执行。 |

上表列出应观察的证据，由各 DP 当前公开入口及具名 writer 产生。只有支持的场景才调用 `decision_receipt`，正式 gate、QG、独审和签收各自沿原 writer。隔离验收中的实际动作和回执属于该隔离运行。

## 必须能区分的分支

| 分支 | 对账结果 |
| --- | --- |
| 模型成功且原主体采纳 | 四段均要关联。已收到或已反解单独记录，执行状态取自实际 writer。 |
| 本地证据优先 | 记录本地判据与真实接回/回执，模型尝试为 0、原始回包为空。按 [调用策略 key](../mw-dp-call-policy/codex_doc.md) 验证 route、w-type、sign-key。保留八 DP 显式模型路径的覆盖。 |
| 发送前拒绝 | 记录明确阶段、原因及已有 `blocked_event_id`，尝试为 0，没有模型回包。未执行动作保持未执行。 |
| 已发结果未知、返回非法、同次证据缺失 | 保留已记录的请求或返回及其实际状态。未确认的动作先对账，自身状态不能记通过。 |
| v0.5 原件回放 | 核真实历史请求、返回和当前参考裁定。历史生产接回与执行缺失仍为空。 |

## 何时可以报八个 DP 都对得上

T08 在现有 36 行报告内加同次关联检查和接回/回执证据指针。用当前公开入口、隔离工作区、匹配本次请求的 faux 回包和原有业务消费者，验证八个 DP 各有一条可追溯的合法模型路径。QG 与旧 auto 保留历史负例，现行合法正例使用独立请求和同版响应。新见证引用现有证据索引，保持九例、36 行的原件对照口径。另核调用策略三路的本地成功与硬检查拒绝。

T09 按每个 DP、每个条目复核，能从回执反查同次请求或本地判据。必须检出错项目/key/任务、旧版本配对、另一尝试的回包、缺原因、借用他人回执、回执写入失败误报执行、重复重放产生副作用。任一应取得的原件缺失、无法关联、身份不可信或未跑，标为未验证或失败。预期拒绝有实际观测时，可作为对应负例的通过证据。

目前已具备范本和对账规则。八个 DP 的现行入口、writer 和回执链须待 T08 实际运行、T09 复核后才能报告 8/8。历史回执和局部测试结果各保留自己的证据范围。
