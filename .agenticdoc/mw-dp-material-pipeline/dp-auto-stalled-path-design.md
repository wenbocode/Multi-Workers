# dp-auto · 卡点后的下一步选择

2026-11-22 设计草案。两份复盘共同提出的问题是：**关键证据迟迟未出现时，原 PM 应把同一事项的下一笔预算用在哪里？** 本篇给既有 dp-auto 增加补充范本，直接沿用 [v0.5 四段合同](reference-comparison-contract.md) 的展示方式。

## 1. 决策单位

一次决策选择一个有界的下一步，以及本次路径允许的条件后继。PM 在准备前写清时点、原目标、第一条缺失的可观察结果，以及该结果为何会改变方向。选项应回答同一问题，例如「在原期限内，是优先直接取得首个真实结果，还是先确认哪个边界会阻止该结果出现？」已有目标优先级须引自原卡或用户决定。事实不足且优先级会改变选择时，先补证。

| 宿主能确认的情形 | 处理 |
| --- | --- |
| 原回执给出明确字段、解析根或范围错误 | 按原事件修正具体输入，先离线验证。比如 continuity 的 key 相对引用和只指标题的 `:1`。 |
| 认领、角色、动作授权、停止或预算校验失败 | 由既有宿主规则决定停下的范围，保存原因。仅在确需外部事实或变更授权时由原 PM 提出具体请求。 |
| 只有一个可行路径 | 原 PM 按既有入口处理。有权且可执行则继续，否则保留阻塞。 |
| 两个候选只改名字，或多一步但不会改变任何后继 | 先合并等价描述。若无法说明区分事实或偏好，退回准备。 |
| 缺关键证据，且有 2–5 条不同、当前可行的路径 | 调用既有 dp-auto，选择一个合法配对。 |

用 `blocked_event_id` 或同事项的真实运行记录定位第一个未达边界。分开读取身份、输入校验、材料准备、传输、响应、业务许可和执行结果。前一节点失败时，下游排查只在能解释失败且仍有权限的范围内进行。确认丢失先对账，状态未知按既有 continuity 处理。

## 2. 材料与发送边界

| 属性 | 来源与校验 | 模型是否看到 |
| --- | --- | --- |
| `desc`、目标、偏差 | 原 PM 写简述，绑定当时的任务卡、目标优先级、最后到达点和第一处缺口。按现有 10 句和精确 1000 tokens 合同校验。 | 简述、当下目标和比较依据。 |
| 证据、未知、术语 | 已存在的工件、首个失败、当时能验证的观察点。引用给必要正文或有来源摘要。标清事实、推断和后来结果，并用时点约束投影。 | 只发送决策时已知事实、必要解释和确会改变选择的未知。 |
| 路径与配对 | 每条路描述行动、可区分的结果、可否定条件、风险、硬上限、条件后继和结束点。PM 起草、宿主核当前可行性，逐对记录优先级与什么证据会反转选择。 | 通过单一 `decision_selection` 的可读判据发送。完整执行命令、写面和关联身份留本地。 |
| 权限及预算 | 宿主从原事项取角色、允许操作、原截止和剩余额度。预算以硬上限对比，包含模型请求、停止或回收、证据写入和报告。每次进入动作前重核。 | 发送必要的动作边界、剩余时间和预留。详细身份、认领凭证和账本留本地。 |
| 预期结果与实际观察 | 设计者的预期、参考答案、后来的真实结果、执行者、运行 ID 以及 PM 事后裁定分别保存。 | 都留本地，避免教模型选答案。 |

候选提交前逐条检查「当前有权且能开始」。等批准或等新预算的执行属于条件诊断，可形成 PM 的后续请求；未获准的动作不能作为当前可执行选项。保留阻塞可以是合法本地结果；只有其相对于另外可行路径有真实的资源或风险取舍，才作为模型候选。预算判断使用路径的最坏有界分支。当前剩余小于 `模型调用硬上限 + 最大合法路径上限 + 报告预留` 时重算可行集合，不能通过减少清理预留凑出两个候选。

## 3. 四段合同与接回

| 段 | 保存内容 | 检查 |
| --- | --- | --- |
| 决策本 | 决策时点、任务边界、来源与未知、预算快照、候选可行性和两两差异，以及冻结的配对表。 | 发布前收齐引用与实质正文。原失败保持原样；修正输入时记录实际变化。 |
| 模型输入 | 使用既有 dp-auto 单题模型投影。保存实际请求，或本地拒绝的阶段、原因和零发送。 | 唯一 `decision_selection`，候选判据有不同的信息价值，缺证和禁止动作不进入请求。 |
| 原始返回 | 真实调用才有原始回包。按该次冻结版本反解 wire、业务路径和依据。 | 未发送为空。模拟返回独立标记。未知 wire、旧配对或材料漂移按现有规则拒绝。 |
| PM 接回 | 核原角色、当前授权、原余量、停止事实及来源新鲜度。记录选中路径、实际工具和结果，或保留未执行。 | 到达点须由真实生产者或宿主记录。后继只在当前结果满足其前提时启动。改任务图走正式重规划，最终质量与签收使用原消费者和 writer。 |

### PM 如何判定动作结果

| 观察结果 | 接回 |
| --- | --- |
| 到达承诺的观察点并取得具备来源的支持证据 | 保存产物、同版本关联和未覆盖范围。按计划进入后继，正式质量结论仍由 QG 核对。 |
| 触发否定条件 | 保存反例，结束该路径。原 PM 决定是否依据既有授权准备新路径或申请范围变更。 |
| 超时、未到达、仅心跳或工具进程返回成功 | 保留实际最后节点、失败/未知和清理状态。没有确认回收时不启动依赖清理的后继。 |
| 发生取消、权限丢失、过期或预算不足 | 原宿主按既有停止范围处理。读取或重放模型建议不恢复权限、时限或预算。 |

Gaze 的取消检查要求**后端在屏障前实际观测信号，并保存明确终态**。只读“published”不能证明未错误取消，只有“queued”也不能证明拒绝已完成。continuity 的观察点应覆盖公开入口、实际 producer、认证、consumer、writer，分别标记到达状态。报表、校验器、原始产物及各层来源都要能关联。

## 4. 两份四段推演

| 案例 | 真实决策时点的可用证据 | 真实门禁判断 | 离线可选路径范本 |
| --- | --- | --- | --- |
| Gaze | 停止 Trace 已预检可稳定打开，尚未读取内容或解析。离线范围已批准。T021 当时只允许在 E 盘核已有证据，D 盘源码写入、构建和运行仍待具体授权。 | 本地做允许的预检与计划核对。缺少原生执行授权时保持当前事项阻塞，模型发送为零。 | 另设明确标注的合成授权、精确工具边界和预算。比较「直接最小原生首验」与「先观察取消控制、再有条件首验」。 [四段范本](evidence/design/stalled-path/gaze.json) |
| continuity | 旧 G 运行 5400 秒到期，缺可用 native 首结果和原栈。记录能证明超时以及产物缺口，无法从中确认根因。 | 旧执行已到期，不能续预算。原 PM 只有在独立、明确的诊断权限与额度内才能启动新的隔离探针。 | 在单独合成的隔离诊断额度内，比较「先跑有界 native 正控」与「先查公开入口的生产接线、适用时才跑正控」。 [四段范本](evidence/design/stalled-path/continuity.json) |

两份附录各包含基于原记录重建的现场判断与合成试算。第三段的手写模拟回包用于核冻结映射，第四段给 PM 接回参考。Gaze 后来的非空 CPU 产物、continuity 后来 25 秒探针取得的调用栈与正式签收，都留在事后复盘中。合成请求尚未计量目标模型精确 tokens 或发送，探针与执行回执均未产生。

## 5. 验证与边界

现有 AC-008/009/011/012/013、18 条标准和 v0.5 九例 36 项照常执行。下列对照为两份附加范本的实施参考。

| 验证输入 | 应查的实际结果 | 任务参考 |
| --- | --- | --- |
| Gaze 仅获离线方向批准，缺原生执行授权 | 原生候选不进入可发集合。保留可合法完成的 E 盘核验和具体缺口。发送数为 0。 | T05/T08 |
| Gaze 合成场景先首验、先取消的两路比较 | 两条不同判据均合法。冻结 `nativeA` 映射后，即便局部准备过程重排也按该次依据反解。把取消控制的结果改成 queued 或回收未知，后继样本阶段保持未启动。 | T05/T06/T08 |
| continuity 旧 G 余额归零，或接回时扣至不足 | 原额度保持归零。合成诊断额度也必须在开始每步前重核；不足时不能减少报告和清理预留来继续。 | T05/T06 |
| continuity 监督器退出成功、被测 native 未结束 | 保存实际 timeout 和首个可知节点。后继认证、QG、signer 保持未到达。 | T08/T09 |
| 两候选只改标签，或无来源的目标优先级会改变结论 | 准备退回，保存等价或待补证诊断。发送数为 0。 | T05 |
| 返回未知 wire、来源漂移、过期映射或状态未知 | 同次映射核对不通过，或由既有 continuity 处置不确定传输。保留返回与接回状态，无新动作、无盲目补发。 | T06/T08 |
| 局部 probe 成功，真实 writer 尚未收到可认证工件 | PM 接回只认局部观察。正式结案由独审证据和既有阶段审计核对。 | T08/T09 |

先确认真实生产者和第一个实际消费端，再扩展异常矩阵。T08 未来用公开入口和隔离替身核执行，T09 复核第一未达节点、证据来源及独审绑定。

建议先观察 PM 能否用该范本实际缩短从卡点到首个可验证结果的时间，并保存决策次数、硬边界拒绝、原预算和独立验收状态。只有反复出现既有 dp-auto 无法表达的独立触发、授权流程或结果消费者，才为 dp-unblock 另行设计合同。重复报错、无正文或监控不完整各用现有机制解决。
