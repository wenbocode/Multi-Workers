# 准备方与窗口的引用检查

1. 使用当前对象/版本已确认的AC与VC原件取完整正文及关系，不按ID猜意思。
2. desc及其它模型可见文本出现缩写时，附本次state.terminology解释；中文简称同样处理，或直接写全称。
3. state.references逐项解释本次引用的AC/VC/发现/工作/条件/入口。发现同编号多义、缺正文、仅文件路径或旧对象定义则重备，不挑有利版本。
4. 所有必要正文必须实际进入冻结body；本地source manifest完整不能弥补模型payload缺定义。只发送本次需要的定义，不灌全项目字典。
5. QG的AC完成情况与VC结果、sign的目标/偏差/QG链仍单独核；词典不是验收证据，不由它推导pass。
6. 已知反证、未知、未执行和成本/范围限制保留。引用/术语变化产生新请求版本，旧回包不套新payload。
7. 返回保存原始response/usage/id，按本次候选反解全部原因与剩余项，confidence和probabilities分别原值；host业务检查仍独立。
8. compose之后增加可区分性检查：逐对说明当前目标/证据为何区分候选、何种条件反转排序，缺证/等价须明确报告；不私删固定候选或为了confidence重发。
9. dp-auto按同一决策单位比较2..5条有界路径，带来源可追溯的目标优先级、区分性证据、信息价值、条件后继、全程上限和停止条件；原预算/次数不刷新。
10. 当前草稿、目标、来源、候选或预算变化使比较报告和发布校验失效。具体prepare工具顺序、模型选择、受限读写及原主体吸收见统一prepare合同；工具均未部署。

机械检查已覆盖注册缩写、本文编号规则和当前状态码；准备方/PM仍负责语义忠实、中文/新术语遗漏与适用范围复核。未解释的新缩写应补定义，不能为了confidence删合理候选或反复发送同一输入。
