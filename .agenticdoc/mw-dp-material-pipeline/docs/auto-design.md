# dp-auto：当前路径设计与可区分性

本节合入v0.5设计验证文档，修订dp-auto和通用prepare Worker合同。其余七个DP沿用本包规范，QG的逐项验收/验证核对、sign的当前同范围QG、全部引用正文与术语解释规则继续适用。

本轮是规范、完整请求样例、本地验证器和真实jev接口实验；专用prepare Worker及下列新工具尚未接入生产。没有重试UEPerformanceFlow/Bearing的业务决策，没有派工、推进门禁或签收。

## 旧例的问题

旧例只说取得可信只读状态或明确失败原因，未排定响应时延与原因诊断的优先级。一次重试和读健康快照都合法，也可以先后执行。两个孤立动作不是充分可比的恢复路径；缺失条件不能靠描述更肯定或删候选补齐。

本版保留旧例为缺证反例，不重新发给模型。新增正例明确标注为新设的合成场景：其目标约定优先取得当前状态，诊断是次级目标。健康快照的服务级范围来自合成来源说明，不能把它说成实际业务现状。本次实验因此不是同一事实下的前后对照，也不证明confidence必然提升。

## 比较的决策单位

| 路径 | 首步 | 成功后的后继 | 失败或不足后的后继 | 最长动作时间 |
| --- | --- | --- | --- | --- |
| retryA：先重试 | 当前只读请求，最多60秒且只一次 | 当前有效响应则结束，不再读健康快照 | 余量足够才读一次健康快照，最多120秒，随后报告失败/未知 | 180秒 |
| diagnoseA：先诊断 | 同服务健康快照，最多120秒且只一次 | 若明确当前服务离线，报告有证据的阻塞并结束 | 健康/不明/读取失败都不能证明接口可用，余量足够才用唯一一次60秒重试，随后结束 | 180秒 |

两条路径共用原300秒余量，保留至少30秒交付报告；开始下一步前重新核实剩余时间。上限不是耗时预测，未给成功概率。取得当前有效响应、报告明确阻塞、路径用完、授权撤销/取消、剩余不足、全局期限到达都须停止。不能以返回上一阶段刷新时间或重试次数。

只比较有界方向和分支含义，模型不接收命令、工具调用参数或完整执行actionplan。具体执行由原主体在接回选择后按原权限制定，并再次核预算/来源/停止条件。

## 可区分性检查

准备方逐对回答：A在哪个已确认目标和证据条件下优于B；B在哪些可观察条件下反过来更好；当前属于哪种情况；还有什么未知可能改变排序。条件和比较必须绑定来源，不能拿“我希望选A”当依据。

结果分为：ready（有依据的权衡）、needs-evidence（缺少会改变排序的目标或事实）、equivalent（在当前目标下后果和成本等价）、invalid（候选重复、越权、超限或绑定错误）。ready不表示唯一正确答案，也不要求某个confidence。缺证/等价是本地准备结果，不增加一个假的dp-auto选项。

旧例应返回needs-evidence：目标没有响应/诊断优先级，超时阶段和快照的新鲜度/适用范围也未说明。新增正例返回ready：优先响应的目标与服务级快照的范围构成可解释差异；仍保留重试可能再次失败、快照实际内容未读等未知。

## 字段发送规则

| 字段 | 来源与组装 | 是否发送 |
| --- | --- | --- |
| state.scenario | 真实场景身份；本例明确写合成参考，无业务执行 | 发送 |
| state.desc | 原PM/实际Worker吸收的目标、偏差、事件、证据与未知，最多10句/1000tokens | 发送 |
| state.material.decision_scope | 当前事项说明，明确选择下一条有界路径，未授权全部恢复动作 | 发送 |
| state.material.objective | 已确认目标的成功条件和有序优先级；未知写未知，不由准备者造偏好 | 发送 |
| state.material.evidence | 当前观测、接口/来源能力、新鲜度、范围、局限、观测/估计性质及来源引用 | 发送 |
| state.material.unknowns | 会改变排序的未知、影响、何种证据可消解及本轮是否可取 | 发送 |
| state.material.constraints | 原余量、只读、一次重试、各步硬上限、报告预留及公共停止条件 | 发送 |
| questions.decision_selection.criteria | 2..5真实路径；各路径首步、信息价值、条件后继、成本上限、风险；只表达一份 | 发送 |
| state.references | 每个引用的必要正文和适用对象；路径/hash不替内容 | 发送 |
| state.terminology / enum_meanings | 当前请求实际使用的术语、缩写、状态或代码解释 | 发送 |
| source-manifest / field-trace | 原件、版本/hash、逐字段来源/变换、发送标记；超限压缩记录遗漏和保留项 | 仅本地 |
| discriminability-report | 逐对比较、缺口、反转条件及准备状态；避免把作者推荐再塞一份题面 | 仅本地 |
| pair-map / path-ledger | 返回别名反解、路径上限机械核对；模型已从criteria看到路径含义 | 仅本地 |
| execution_plan / owner / budget_ref | 原身份、工具命令、原预算账本及真实授权检查 | 仅本地 |
| expected / 校验器过程 / request hash | 样例作者预期、编制过程及传输核验元数据 | 仅本地 |

仅把影响选择的预算余量和约束投影入模；本地budget_ref仍是实际执行依据。正文较大时由同一准备者在原预算内压缩，保留否定、失败、未知、范围与全部候选判据；仍不足则输出具体缺口，禁止截尾/只给路径。

## 影响范围和接续

通用prepare流程在compose之后、validate之前新增可区分性检查；所有DP检查候选语义是否重叠、是否缺证，但不允许裁剪固定闭集。dp-auto的2..5动态候选另核同一决策单位、有界路径、信息价值、后继和停止。QG不把合法的多个fix原因删成一个，route不把不同职责入口合并。其余七个DP的字段与本轮已保存请求不改。

原PM/实际Worker继续是责任主体；prepare仅整理材料，不能代替独立review或当前Worker自评。新增检查失效只使当前准备不能发布，不成为全局运行停止门。原主体按continuity可补取、采用已有合法本地处置或如实回报；不重置预算、不开新审批、不冒充DP结果。

生产接入仍需实现受限工具、顺序守卫、源变化失效、模型选择记录、PM吸收和host分支复核。本轮可运行的是合成材料验证器，不能宣称它已经拦截真实值守窗口。
