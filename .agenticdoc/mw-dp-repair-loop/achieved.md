# mw-dp-repair-loop

## 系统行为变化

- 正常裁决继续返回 selection、basis 和既有回执。恢复反馈返回一个 next，带当前责任方、对象和完成条件。材料拒绝使用草稿修正标识。相同快照下预览与正式校验相互矛盾时，交框架维护方核对。
- 恢复状态随草稿持久化。首次拒绝计零，实际修复并复验通过原规则时清零，连续三次无进展后暂停对应事项。重复版本保留原结果。宿主使用已绑定的阶段、任务或重派关系关联同一事项。新证据经核验解决原缺口，或收到绑定草稿的有效人工批准后，沿原事项恢复。
- 裁决请求超时后，重新打开窗口会先核对原动作。发现已保存的正式结果后，使用原动作标识读取回执。撤回授权、父取消和预算限制沿现有约束生效。

## 验收证据

- 102 项 Python 测试通过，覆盖连续无进展计数、两种恢复条件、旧草稿接续、原回执复用、独立任务实际入队和正式 QG 修复及独审。四条验收标准均有命令与源码快照。[Python 证据](evidence/codex-pm/self/1795448368843352300-vup0a8la/result.json)
- 38 项窗口测试通过，覆盖一个恢复动作、正常裁决省略 next、两处字段修正后单次发送、相同快照校验不一致及超时重开后的零重发。[窗口证据](evidence/codex-pm/self/1795448403139102700-ln3ethd8/result.json)
- 完整 npm 检查在隔离源码副本通过。[检查输出](evidence/npm-check.txt)
- 同一副本运行扩展连续性套件，分别用 HEAD 版本和本次版本的窗口工具。两次失败用例名称完全相同，共 29 项，主要未观察到夹具预期的派工。[对照结果](evidence/continuity-baseline.json)

## 遗留

验证由 Codex PM 执行，覆盖隔离项目和本机回环。Gaze、UEPerformanceFlow 和 RenderPerformance 的实窗验证由 `mw-dp-window-acceptance` 接续。扩展连续性套件的 29 项失败保留在对照记录。
