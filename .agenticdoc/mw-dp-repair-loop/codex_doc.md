## 目标

让 PM 收到 DP 或宿主的反馈后，能在原授权内执行一步、回收结果并重新评估。真实阻塞只停止对应事项，仍可推进的工作由现有责任人继续。

## 范围

控制与目标工作区均为本仓库。负责 `ask_decision` 反馈消费、原事项标识与计数、PM 接回、复验及交接。复用 `decision-tool.ts`、现有 handoff、队列及业务 writer。诊断由材料准备入口提供。

## 验收标准

- AC-001: 材料拒绝返回一个带责任方、修正对象及完成条件的 next。原草稿两步修正后正式发送 1 次。相同快照出现校验矛盾时返回框架恢复动作。
- AC-002: 用固定输入断言计数 0 → 1 → 2 → 0 → 1 → 2 → 3 并暂停。原样重发、轮换旧版本和换 trigger 均不变更计数。新证据或明确授权沿原事项恢复。
- AC-003: 正常裁决省略 next，原执行入口及回执照常工作。QG fix 后读到产品修复和独审结果，pass 后读到正式结果。
- AC-004: 请求超时后重开窗口，新发送数为 0，找回原结果后复用回执。缺授权或预算、父取消时新增受限动作数为 0。暂停一项时，另一项已授权的任务仍可实际入队。

## 关键决策

用户已确认按同一事项连续三次无进展暂停，确认按新证据或明确恢复授权接回原事项。相同快照 ready 后的正式材料拒绝交框架维护。原始证据沿用已有审计记录。

## 设计草案

### 事项、快照与状态

同一 DP 可同时处理多个独立事项。宿主从当前项目、key、DP 和可核验的业务对象建立事项引用，优先使用现有的阶段、门禁、审查对象或父任务关系。重派时沿已验证的父关系继承事项。只在宿主能确认确有独立业务对象时建立新事项。草稿、证据版本和现有去重指纹记录某一版尝试，换材料或重开窗口仍指回原事项。恢复时用当前 claim 或运行事实核对归属。新窗口接续需要复核上一窗口留下的动作和效果。

优先复用本机草稿的原子保存、现有预算和正式回执。每个事项保存当前草稿引用、连续无进展次数、最近已核对版本和本轮后续动作。草稿更新、复验结果和计数在同一事项上串行记录。旧反馈与执行回执可回查。

### 一步反馈及复验

材料拒绝、结果未知或现有执行入口受阻时，宿主返回一个恢复动作。用户可见正文给出当前阶段、责任方、一个动作和完成条件，全部诊断保留供修正。示例是「材料准备阶段发现证据越界。PM 核实末行，用原草稿修正行段后重新提交」。提交时宿主读取当前证据，复验草稿。材料通过时在这一次提交中发给 DP。

首次诊断建立基线。每次以宿主实际验证过的版本为准。原修正目标已通过复验时清零。如果新校验未走到原规则、诊断截断或同字段冲突，先核实，不能仅凭缺口未显示就认定已修好。相同版本复读原结果。已经关闭的同一缺口因撤回修复而再次出现时，保留已有进展证据和父预算，不能用两个旧版本轮换延续尝试。

第三次无进展时先由 PM 复盘当前事项，选择补证、改可执行计划或交给框架维护方。恢复必须附新证据或明确授权，并复核剩余预算和当前绑定。合法的其他事项继续调度。

### 正式结果与边界

正常裁决沿用 selection、basis、现行执行入口及 consumed、executed、settled 回执。正式 QG fix 回到产品修复、复验和独立审查。质量通过进入适用的现有执行入口，再核对实际产物或回执。恢复反馈在材料拒绝或现行路径无法继续时提供。DP 不可用时，PM 沿既有授权和允许的执行入口继续。未知效果先按原动作核对真实队列或产物，确认后才决定是否重试。缺外部授权、明确停止、父取消和预算耗尽沿现有规则生效。需要用户时给出实际缺失的事实或授权及恢复条件。

## 执行与验收

用户确认正常执行路径沿用原流程，恢复才返回 next。实现和验收由 Codex PM 执行，无在途 Worker。公开窗口和 CLI 的验收见 [achieved.md](achieved.md)。
