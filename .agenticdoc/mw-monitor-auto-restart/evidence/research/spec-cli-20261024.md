## Facts
- mw.py:5565 _monitor_open always enters ensure_instance with detached starter; --no-open skips boot-code/window spawn (:5598+). Existing AttachedInstance returns reused=true; replacement started child publishes new identity (:5480+) only when PID matches proc.pid. Output scrubs boot codes (:5371+).
- Starter parent holds ensure_instance's start_lock through child publication and health (:5472 / decision_monitor.py:2687). Child entry calls serve then joins shutdown thread before process exit (mw.py:5775–5828); do not invoke _monitor_stop then _monitor_open separately outside lock, which creates a race.
- status/stop are separate read-only/stop paths (mw.py:5648–5748) and must not inherit automatic start/replacement.
- decision_monitor.py:2709 incompatible live instance currently refuses before authenticated health. New path must authenticate health and match recorded identity before requesting shutdown; protocol/code mismatch is not identity failure if recorded fields exactly match old server.
- AttachedInstance.stop(:2539) sends authenticated /api/shutdown and confirms port ECONNREFUSED, waits own state disappear, never deletes remote state/secret. It can return stopped=true with detail of rejected request or retained files; automatic restart must NOT treat this alone as successful graceful stop.
- MonitorInstance.stop(:2377) owns identity-file removal before listener close; request_shutdown asynchronously stops after response flush. Files removal isn't under start_lock (:2407), so new publication must wait until old cleanup/process truly finished. CLI child join is relevant process-exit assurance.
- ensure_instance(:2663) already supports injected liveness/start_ms/port probes/sleep and starter, conservative stale recovery, health_wait. Most behavioral implementation can stay in decision_monitor.py with existing mw.py call automatically benefitting, no new CLI syntax required.
