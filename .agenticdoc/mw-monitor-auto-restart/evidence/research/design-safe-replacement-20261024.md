## 发现 / alternatives
D001: implement CLI stop→open outside lock (simple but TOCTOU two starts) versus ensure_instance opt-in replacement under existing lock (atomic coordinating boundary; recommended). Existing default refusal preserved for intentional low-level serve/general API consumers; CLI bare/open is opt-in writer.
D002: port-refusal+own-state removal (existing library lifecycle closure sufficient for in-process tests) versus literal detached old PID exit gate (stronger confirmed-exit interpretation requested by user; recommended for automatic CLI replacement). RQ1 recommendation of no mandatory PID gate conflicts with confirmed actual exit boundary. Do not weaken requirement to accommodate tests: fake probes or detached synthetic old process can test it. Self-PID automatic replacement is refused. Process start time changed proves OLD identity gone, not authority to stop new owner; port/foreign-state checks still block where necessary.
D003: monitor module-only hash (current asset edits invisible) versus deterministic hash of monitor module + ordered dashboard HTML/CSS/JS names+bytes (recommended for known stale-page bug). No protocol/state-schema bump; old hash differs once, identity checks use recorded old hash unchanged. Same source bytes stable; individual asset edit must change hash. Additional dynamically imported Python module invalidation beyond current known scope remains residual, not full dependency cache proof.
D004: wait/retry concurrent open (friendlier but new timing/retry policy) versus existing short start-lock conflict (recommended minimal fail-closed AC006). No threshold weakening/retry loop/lock deletion.
D005: change AttachedInstance.stop contracts (broad API impact) versus strict replacement validator over existing result + injected helper seams/mock probes for deterministic tests (recommended). Explicit status/stop behavior unchanged.

## 结论 → 决策映射
Design D001–005 propose conservative path: project+liveness → opt-in check → authenticated health and full identity/file/secret reread → authenticated stop → strict stopped=true/detail=null/probe=refused/state=absent gate → bounded old-identity-dead confirmation under lock → guard verify and reread no state/secret before existing start+health → boot/window only after healthy replacement. Error at any point: no replacement/kill/clear; old server's own successful shutdown cleanup may already have happened, report honestly rather than promise rollback.
Asset fingerprint inclusion and PID gate are explicitly proposed design details awaiting human review, not implemented or tested. RQ1 complete/acked; worker dispatch paused after two unintended dp1 API calls; future source changes PM serial only.
